课堂讲义（板书）

讲解0. 这节课到底学什么

前两章都在「用」模型，这一章要「看穿」模型。面试官常丢给你一个 config.json 问「这模型多少参数、内存多少」——你要是能当场手算，身价立刻不一样。定位是架构师不是研究员：公式只讲物理含义，不推导，全部落到可手算的数字。

一句话记住：参数量 = 所有「有数值可训练」的矩阵元素总数；看懂 config 就能算，不需要读论文。

讲解1. 板书①：Transformer 一层长什么样

不管多花哨的模型，一个解码层就是两个子块 + 两条残差。先把结构记牢。

一个 Transformer 解码层： ┌─ ① 注意力块 ───────────────────────── │ LayerNorm → Q/K/V/O 四个投影 → 残差相加 └──────────────────────────────────── ┌─ ② FFN 前馈块 ─────────────────────── │ LayerNorm → 上投影 → 激活 → 下投影 → 残差相加 └──────────────────────────────────── 两个配角（参数极少，先记住作用）： 残差 residual：把输入原样加回来，防止深层网络梯度消失 LayerNorm ：逐 token 归一化，每层 2 个，参数量 ≈ 2×hidden 参数大户只有两处： 注意力里的 Q/K/V/O 投影　＋　FFN 里的 上/下投影矩阵

讲解2. 板书②：每个权重矩阵的参数量算法

一个权重矩阵的参数量 = 输入维 × 输出维。就这么简单，剩下的是套结构。

矩阵参数量 = 输入维度 × 输出维度
先定义符号（背下来）： h = hidden_size 隐藏维（模型主宽度） L = num_hidden_layers 层数 I = intermediate_size FFN 中间维 V = vocab_size 词表大小 a = num_attention_heads Q 头数 k = num_key_value_heads KV 头数 d = head_dim = h / a 每个头的维度 每层注意力（四个投影）： Q 投影: h × (a·d) = h×h → h² K 投影: h × (k·d) → h·k·d V 投影: h × (k·d) → h·k·d O 投影: (a·d) × h = h×h → h² 合计 ≈ 2h² + 2h·k·d　（GQA 时 k 小，K/V 项就小） 每层 FFN（SwiGLU，共 3 个矩阵）： gate: h × I up: h × I down: I × h 合计 = 3·h·I 每层小计 ≈ 2h² + 2h·k·d + 3h·I（忽略 LayerNorm，占比 <0.01%）
注意点：GQA 让 K/V 的输入维变成 k·d 而不是 h，所以 K/V 矩阵比 Q/O 小很多——这是省参数的关键。

讲解3. 板书③：打开 Qwen2.5-3B config.json 手算

现在把真实数字代进去。先把关键字段抄出来，再一层层算。

Qwen2.5-3B config.json 关键字段： hidden_size = 2048 num_hidden_layers = 36 intermediate_size = 11008 vocab_size = 151936 num_attention_heads = 16 num_key_value_heads = 2 tie_word_embeddings = true 推导：head_dim d = h / a = 2048 / 16 = 128 代入每层公式 2h² + 2h·k·d + 3h·I： 2h² = 2 × 2048² = 2 × 4,194,304 = 8,388,608 2h·k·d = 2 × 2048 × 2 × 128 = 2 × 524,288 = 1,048,576 3h·I = 3 × 2048 × 11008 = 3 × 22,544,384 = 67,633,152 每层 ≈ 8,388,608 + 1,048,576 + 67,633,152 = 77,070,336 ≈ 77.07 M 36 层合计： 77.07 M × 36 = 2,774.5 M ≈ 2.77 B 加 Embedding（V × h）： 151936 × 2048 = 311.2 M （tie=true → 只算一次，输出层复用） 总计 ≈ 2.77 B + 0.31 B = 3.086 B ≈ 3.09 B ✅ 官方 3.09B — 对上了！
看穿模型：FFN 占了大头（每层约 67.6M，占总参数约 79%）——所以优化模型体积，FFN 才是主战场。

讲解4. 板书④：Embedding 到底算不算？权重共享是什么

这是最容易被问倒的细节，讲清楚就能显专业。

Embedding 计不计入参数量？ 它是真实存在的权重 V × h（151936 × 2048 = 311 M）， 当然算进「总参数量」。 但有些端侧报告只关心「推理时反复读的 transformer 权重」， 会把 embedding 单列 —— 说清口径就行，别被绕晕。 输出层 lm_head 与权重共享（tie embeddings）： 模型最后要一个 V × h 的矩阵把隐藏态映射到词表分数。 小模型常让 lm_head 直接复用 embedding 矩阵（tie）。 Qwen2.5 config 里 tie_word_embeddings = true → 只算一次。 若为 false，则要 额外 + 一份 V×h（多 311 M）。 LayerNorm 参数： 每层 2 个 × 各 2×h（weight+bias）→ 本模型每层 8192， 36 层 ≈ 0.29 M，占总量 <0.01%，手算可直接忽略。

讲解5. 板书⑤：参数量 → 内存（接回第 1、2 章）

算出参数量只是开始，架构师要立刻换算成内存。乘位宽、除 8。

参数量 → 权重内存 = 参数量 × 每参数字节数 全 fp16：3.086 B × 2 B = 6.17 GB int8 ：3.086 B × 1 B = 3.09 GB int4 ：3.086 B × 0.5 B = 1.54 GB + scale 开销（约 3%） → 实际 ≈ 1.6 GB 这就是第 1 章「3B int4 ≈ 2GB」的来源： 参数 1.54 GB + 量化开销 + 运行时缓冲 → 约 2 GB（保守口径）。 再接第 4 章： 权重 1.6 GB + KV Cache（8K ≈ 288 MB） → 端侧常驻内存模型。

讲解6. 板书⑥：5 分钟手算口诀

五步走（背下来，面试现场就能算）： 1) 抄 6 个数：h, L, I, V, a, k 2) 算 head_dim d = h / a 3) 每层 = 2h² + 2h·k·d + 3h·I 4) 总权重 = 每层 × L 5) 加 embedding：tie 则 +V·h 一次，否则 +2×(V·h) Qwen2.5-3B 复算： d = 2048/16 = 128 每层 ≈ 77.07 M → ×36 = 2.77 B → +0.31 B = ≈ 3.09 B 不同口径要报清楚：「transformer 权重 2.77B，含 embedding 3.09B」。

讲解7. 板书填空：参数量拆解空表

填出 Qwen2.5-3B 每层的三项（用 h=2048, k=2, d=128, I=11008），再展开答案。

项目公式参数量
注意力 Q/O（2h²）2 × h²?
注意力 K/V（2h·k·d）2 × h × k × d?
FFN（3h·I）3 × h × I?
每层合计三项相加?
点击展开答案
Q/O：2 × 2048² = 8,388,608 K/V：2 × 2048 × 2 × 128 = 1,048,576 FFN：3 × 2048 × 11008 = 67,633,152 每层合计 = 8,388,608 + 1,048,576 + 67,633,152 = 77,070,336 ≈ 77.07 M × 36 层 = 2.77 B；+ embedding 0.31 B = 3.09 B FFN 占比 ≈ 67.63 / 77.07 ≈ 88%（每层内）。

面试话术

可直接背

「给我一个模型的 config.json，我就能算出参数量。每层的参数是 2 倍 hidden 的平方，加 2 乘 hidden 乘 KV 头数乘 head_dim，加 3 乘 hidden 乘 intermediate，后面再乘层数，最后加上 embedding 的 vocab 乘 hidden。以 Qwen2.5-3B 为例，hidden 2048、36 层、intermediate 11008、词表 15 万、Q 头 16、KV 头 2，head_dim 128，每层约 77M，36 层约 2.77B，embedding 约 0.31B，因为 tie_word_embeddings 是 true 只算一次，总共约 3.09B，和官方一致。FFN 占了参数量的将近八成，所以如果要压模型体积，重点在 FFN。」

能力标签：能看懂 config、能现场手算参数量与内存——模型结构与参数分析能力。

RK3576 特别提示

  • 3.09B int4 ≈ 1.6 GB，加上 KV Cache 与运行时缓冲，3576 的 16 GB LPDDR5 余量充足。
  • FFN 占参数近八成，是量化与压缩的主战场；注意 FFN 权重对精度更敏感。
  • 若 config 里 tie_word_embeddings = true，别把输出层重复计一次，否则参数量会算大。
  • 回报参数量时务必说清口径（是否含 embedding、是否含 lm_head），这是专业度的体现。
