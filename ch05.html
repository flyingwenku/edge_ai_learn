课堂讲义（板书）

讲解0. 这节课到底学什么

第 7 章你知道 decode 是「逐 token 生成」。但每生成一个 token，模型要去看前面所有 token 的信息——如果每次重算，代价爆炸。KV Cache 就是为此而生，代价是内存随上下文线性增长。算得清它，你才算摸到端侧 LLM 的门槛。这一章的 KV Cache、瓶颈定位，以及它的分页管理（PagedAttention）与量化，都是面试的必问题。

一句话记住：KV Cache 是「时间换空间」；端侧跑 LLM，空间（带宽）往往比时间（算力）更致命。

讲解1. 板书①：KV Cache 为什么存在

Attention 的本质：新的 Query 要和前面所有 token 的 Key 做点积、再用结果去加权所有 Value。问题在于这些 K、V 每步都会用到。

没有 Cache 会怎样： 生成第 100 个 token 时，要把前 99 个 token 的 K、V 全部重算一遍； 生成第 101 个再重算前 100 个…… 计算量 ~ N² 爆炸。 有 Cache 之后： 每个 token 的 K、V 只算 一次，算完就存起来； 第 N 个 token 直接用缓存里的 [K1…K_{N-1}]，只算自己这份。 代价：省了算力，但要一块内存常驻 —— 这就是 KV Cache。 它随上下文长度线性增长，是端侧内存的头号变量。

讲解2. 板书②：KV Cache 公式 + 手算 Qwen2.5-3B

公式不长，但每个符号都要理解物理含义。别背，按「2 份 × 层 × 头 × 维度 × 长度 × 字节」念出来。

KV_bytes = 2 × layers × kv_heads × head_dim × seq_len × bytes
逐项物理含义： 2 = K 和 V 两份（各存一份） layers = 层数（每层都有自己的 K/V） kv_heads = KV 的头数（GQA 时 < Q 头数） head_dim = 每个头的维度 seq_len = 缓存了多长上下文（token 数） bytes = 每个数的字节：fp16 = 2，int8 = 1 Qwen2.5-3B 假设：layers = 36, kv_heads = 2, head_dim = 128, fp16 每 token = 2 × 36 × 2 × 128 × 2 = 2×36 = 72 = 72×2 = 144 = 144×128 = 18432 = 18432×2 = 36864 B ≈ 36 KB / token 长度换算（× token 数）： 1K = 36 KB × 1024 ≈ 36 MB 4K = 36 KB × 4096 ≈ 144 MB 8K = 36 KB × 8192 ≈ 288 MB
秒算口诀：「每 token 36 KB」——记住这个数，4K/8K 随口就来。

讲解3. 板书③：MHA → MQA → GQA → MLA 演进

为什么 KV 头数可以比 Q 头数少？因为KV 才是内存大头，业界想尽办法砍它。

四种注意力，砍的就是 KV 头数： 【MHA 多头注意力】Q/K/V 头数全部相等 = 16 每 token = 2×36×16×128×2 = 288 KB　← 最贵 表达力最强，但 KV Cache 最大 【MQA 多查询注意力】K/V 只有 1 个头，所有 Q 共享它 每 token = 2×36×1×128×2 = 18 KB　← 最省 省 16 倍，但精度掉得明显，大模型少用 【GQA 分组查询注意力】K/V 头数 = 2（16 个 Q 分成 8 组共享） 每 token = 2×36×2×128×2 = 36 KB　← 工业主流 Qwen2.5 / Llama3 都用它：省内存又保精度 【MLA 多头潜在注意力】DeepSeek：把 K/V 压成低维隐向量再存 比 GQA 更省，但结构复杂、NPU 不友好
面试点：「GQA 是 MHA 省内存、MQA 保精度的折中，Qwen2.5 用 GQA（K/V=2 头）。」

讲解4. 板书④：算力瓶颈 vs 带宽瓶颈（算术强度）

判断瓶颈不用跑测试，一个比值就够——算术强度。

算术强度 AI = 计算量(FLOPs) ÷ 访存量(Bytes)
判据： AI 大 → 每次搬数都能算很多次 → 算力瓶颈（compute-bound） AI 小 → 数据搬进来还没算几下就没了 → 带宽瓶颈（memory-bound） 机器的「脊点」= 峰值算力 ÷ 内存带宽： RK3576：6 TOPS int8 ÷ 35 GB/s = 6000 / 35 ≈ 171 FLOP / Byte 只要任务 AI < 171 → 判为带宽瓶颈 decode 的 AI 有多小？ 3B int4 权重 ≈ 2 GB，生成 1 token ≈ 2×3G = 6 GFLOP AI ≈ 6 GFLOP ÷ 2 GB = 3 FLOP / Byte 3 ≪ 171 → 严重带宽瓶颈 prefill 的 AI 呢？ 512 token 一次并行，权重读一次算一大片 → AI 高，偏算力瓶颈

讲解5. 板书⑤：为什么 RK3576 上是带宽瓶颈

三个数字摆一起，结论自动浮现。

三个数字： NPU 算力 6 TOPS int8 （很快，够用） 内存带宽 ≈ 35 GB/s （真正瓶颈） 模型 int4 3B ≈ 2 GB （每步都要整个读一遍） 理论天花板： decode 理论最高 = 35 GB/s ÷ 2 GB = 17.5 token/s 再扣掉读 KV Cache、算子开销、非理想访存 → 实测 5~10 tok/s 推论（重要）： 把 NPU 换成算力翻倍的芯片、但带宽不变 → decode 几乎不变 把模型从 int4 压更狠、或上 GQA/KV 量化 → decode 明显变快 结论：3576 上 LLM decode 的天花板由带宽决定，不是算力。 优化方向 = 「少读、少存」，不是「堆算力」。
一句话结论：带宽 35 GB/s ÷ 模型 2 GB ≈ 17 tok/s，这就是端侧 LLM 的物理上限。

讲解6. 板书⑥：瓶颈定位速查

现象 → 判定 → 对策 首字慢 / 长 prompt 卡 → prefill 偏算力 → 批处理、分块 prefill 出字慢 / 逐 token 卡 → decode 带宽瓶颈 → 量化、GQA、KV 量化 上下文越长越卡 → KV Cache 膨胀 → 缩短上下文、KV Cache 量化 换更强 NPU 却没用 → 说明卡在带宽 → 先查带宽，别急着换芯片 速算模板（背下来）： 1) KV / token = 2×L×kv_heads×d×bytes 2) 总量 = ×seq_len 3) 瓶颈 = 比较 AI 和脊点 (3576 ≈ 171)

讲解7. 板书⑦：PagedAttention —— 把 KV Cache 分页分块

KV Cache 体积大、生命周期又长，怎么「摆」在显存里，本身就是一个系统问题。PagedAttention 借用了操作系统的虚拟内存分页思想。

问题：KV Cache 怎么分配内存才不浪费？ 朴素做法：给每条请求预留一段连续显存，按最大长度开。 → 长度未知 ⇒ 要么开太大（预留浪费）， 要么开太小（要重新拷贝、碎片化）。 → 连续分配下，显存利用率常常只有 20~40%。 PagedAttention 的做法：分页 / 分块 把 KV Cache 切成固定大小的 block（块，如 16 个 token 一块）， 按需分配、块之间不必连续， 用一张 block table（块表）记录「逻辑块 → 物理块」的映射。 和 OS 里「物理页 + 页表」几乎一样： · 逻辑上的 token 序列 ↔ 虚拟地址空间 · 物理 block ↔ 物理页框 · block table ↔ 页表 好处： ① 消除连续分配浪费 → 块内最多浪费不到 1 块（如 16 token） ② 消除外部碎片 → 显存利用率可提到 90%+ ③ 公共前缀的 KV 可被多条请求共享，进一步省内存 → 同样显存能塞下更多并发请求，吞吐大涨。 它是谁的核心机制：vLLM 靠 PagedAttention 起家， 如今已是主流推理框架的标配思想。
面试点：「PagedAttention 把 KV Cache 按固定 block 分页分配、用块表映射，类比 OS 虚拟内存——解决内存碎片、提高并发时的显存利用率，是 vLLM 的核心机制。」

端侧要能讲取舍：RK3576/NPU 上不一定直接跑 vLLM（NPU 的 KV Cache 通常由运行时静态管理、形状更固定），但面试问「KV Cache 怎么管理、怎么提高并发」时，你要能把分页这套原理和它的代价（块表开销、块碎片、实现复杂度）说清楚。

讲解8. 板书⑧：KV Cache 量化（fp16 → int8 / int4）

权重能量化，KV Cache 也一样。它直接决定 decode 阶段要读多少字节——而 decode 正是带宽瓶颈。

KV Cache 量化 = 把每个 K/V 数从 fp16 压成 int8 / int4 fp16 → int8：每个数 2 → 1 字节 → 内存/带宽 减半 fp16 → int4：每个数 2 → 0.5 字节 → 内存/带宽 降到 1/4 对本章结论的意义： decode 是带宽瓶颈，KV Cache 与权重抢同一块带宽； 上下文越长，KV 占比越大（甚至超过权重）→ KV 量化直接给带宽「减负」，是端侧长上下文的关键手段。 但代价：精度更敏感！ 权重只在前向里「被读一次」，KV 却要在每一步注意力里被反复用到。 量化的误差会沿着上下文长度累积、被 attention 放大 → 同样位宽下，KV 量化对 PPL 的影响通常比权重量化更明显。 工程折中：常用 int8 KV（几乎无损、直接减半）； int4 KV 收益大，但要用分组 / per-head scale 等技巧并更小心验证。
权重量化 vs KV 量化（对比，背下来） 维度 权重量化 KV Cache 量化 ───────────────────────────────────────────── 压什么 模型参数（静态） 运行时产生的 K/V（动态） 省什么 内存占用、读取带宽 内存占用、KV 读取带宽 何时生效 加载即定 随上下文增长 误差特性 一次性、可控 逐步累积、被 attention 放大 精度敏感度 相对温和 更敏感（同 bit 掉 PPL 更多） 常用位宽 int8 / int4 int8（稳）/ int4（激进） 端侧价值 模型装得下 长上下文不爆、带宽减负 一句话：权重量化让「模型变小」，KV 量化让「上下文变便宜」。 两者叠加，才是端侧长上下文的完整解法。
面试点：「KV 也能量化，fp16→int8 直接减半带宽；但 KV 参与每一步注意力，误差会随上下文累积，所以对 PPL 比权重量化更敏感，端侧一般先上 int8 KV。」

「KV Cache 是为了避免 decode 时重算历史 K/V，公式是 2 乘层数乘 KV 头数乘 head_dim 乘序列长度乘字节数。以 Qwen2.5-3B 为例，36 层、GQA、KV 头数 2、head_dim 128，每 token 约 36 KB，8K 上下文大概 288 MB。判断瓶颈我用算术强度：计算量除以访存量。RK3576 的脊点是 6 TOPS 除以 35 GB/s 约等于 171，而 decode 每 token 只做 2×3G 的浮点运算却要读 2 GB 权重，算术强度约等于 3，远低于 171，所以 decode 是带宽瓶颈。理论天花板是 35 GB/s 除以 2 GB 约 17 token/s，实测 5 到 10。所以优化方向是量化、GQA、KV Cache 量化去少读少存，而不是堆算力。KV Cache 的内存管理上，主流是 PagedAttention——把它切成固定大小的 block 分页分配、用块表映射，思路跟操作系统虚拟内存分页一样，能消除碎片、提高并发时的显存利用率，是 vLLM 的核心机制；端侧不一定直接跑 vLLM，但原理和取舍要讲得清。KV 本身也能量化，fp16 到 int8 直接减半带宽、到 int4 降到四分之一，但 KV 参与每一步注意力、误差会随上下文累积，所以比权重量化对 PPL 更敏感，端侧长上下文我一般先上 int8 KV。」

能力标签：能秒算 KV Cache、能定位算力/带宽瓶颈、能讲清 KV 内存管理与量化——内存测算、瓶颈诊断与 KV 优化能力。

RK3576 特别提示

  • 3576 内存带宽约 35 GB/s，是 LLM decode 的硬天花板；算力 6 TOPS 反而不是瓶颈。
  • LPDDR5 双通道才能跑满带宽，工程上要注意内存颗粒与频率配置。
  • KV Cache 与模型权重抢同一块带宽，长上下文会同时拖慢 decode。
  • 端侧长上下文优先考虑 KV Cache int8 量化（直接减半带宽压力）；int4 KV 收益更大但精度风险高，需实测 PPL。
  • PagedAttention 的分页思想要会讲，但 3576 的 NPU KV Cache 多由运行时静态管理，不一定直接跑 vLLM——面试讲原理与取舍即可。
