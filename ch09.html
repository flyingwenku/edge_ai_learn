第 9 章：模型转换与量化部署

章节目标：把「会算」变成「会落地」——用 rknn-toolkit2 把 3B 模型转成 NPU 能吃的 .rknn，做完校准、量化、精度对比，最后能拍板回答面试官那句：「这个量化方案能不能上线？」

课堂讲义（板书）

讲解0. 这节课到底学什么

第 1~2 章你在纸上算：模型多大、用哪种量化、多少 tok/s。但架构师不能只会算，还得真的把模型塞进 NPU。这一步 90% 的人会翻车——不是报错就是精度崩，原因几乎都出在校准集和量化配置上。

你要能三件事：① 说清整条转换流水线每一步在干嘛；② 用一份配置把模型转出来并跑通；③ 量化前后精度差多少、差到什么程度就不能上线。

讲解1. 板书①：整条流水线（HF → ONNX → RKNN → .rknn）

NPU 不认识 PyTorch，只认识瑞芯微自己的 .rknn。所以中间要有「翻译」：先把 PyTorch 换成通用格式 ONNX，再由 rknn-toolkit2 编译成 .rknn。

端侧 LLM 转换流水线（四段） ① 原始权重 HuggingFace / PyTorch (.safetensors) │ 取到模型 + tokenizer ▼ ② 转换准备 ONNX 导出 / 直接喂 rkllm 的权重转换脚本 │ 小模型走 onnx → rknn-toolkit2 │ LLM 走 rknn-llm（rkllm）一键转换 ▼ ③ 量化 + 编译 rknn-toolkit2 / rkllm │ build(do_quantization=True, dataset=校准集) ▼ ④ 产物 .rknn （NPU 直接加载，与硬件绑定） 关键：.rknn 是"过编译"的——它针对目标平台（rk3576） 做过算子映射和量化，换个平台要在新平台重转。 所以 target_platform 一定要写对。

两条路线怎么选：小模型/ViT 走 onnx + rknn-toolkit2；LLM 走 rknn-llm（rkllm），它内部封装了量化与权重打包，一条命令出 .rkllm。

讲解2. 板书②：量化配置三件套

PTQ（训练后量化）能不能成，就看这三个参数。少一个都跑不起来，配错任何一个精度就崩。

三件套 —— 缺一不可 ① dataset（校准集） 必须给，且要真实 作用：让量化器"看"一遍真实输入，统计每个张量的动态范围 形态：rknn-toolkit2 用小样本 bin/npy； rkllm 用一段真实 prompt 文本 ② quantized_dtype（量化类型） 告诉编译器：权重几位、激活几位 w8a8 权重 8 / 激活 8 → 最稳，3576 首选 w8a16 权重 8 / 激活 16 → 精度更高，慢一些 w4a16 权重 4 / 激活 16 → LLM 端侧主流，省内存 ③ quantized_algorithm（量化算法） normal 最直接（max 定标），快、够用 mmse 最小化量化误差，慢一点、精度更好 kl_divergence 分布对齐，对激活敏感场景好 一句话：dtype 决定"多省"，algorithm 决定"多准"。
rkllm 转换配置示例（config.json） { "target_platform": "rk3576", "model_path": "Qwen2.5-3B-Instruct", "quantized_dtype": "w4a16", // 权重 4 位，激活 16 位 "quantized_algorithm": "normal", "num_npu_core": 1, "group_size": 128 } rknn-toolkit2（小模型）等价写法 rknn.config(quantized_dtype='w8a8', quantized_algorithm='mmse', optimization_level=3) rknn.build(do_quantization=True, dataset='dataset.txt')

讲解3. 板书③：校准集怎么做（决定成败）

量化的本质是「给每个张量找一把尺子」。尺子的量程由校准数据决定——你喂什么，它就以为世界长什么样。喂错，线上就崩。

校准集三条军规 ① 要真实 用产品里真实的输入分布。 聊天模型 → 用真实用户问答；别用随机噪声。 用随机数据校准 = 上线后精度崩的头号原因 ② 要够量 LLM：100 ~ 500 条代表性 prompt； 视觉小模型：100 ~ 500 张真实图片。 太少 → 统计不稳；太多 → 转换慢，收益递减。 ③ 要覆盖 长度覆盖短/中/长（如 64 / 512 / 2048 tok）； 内容覆盖你的真实任务（客服/翻译/代码都要有样本）。 dataset.txt 长这样（每行一条样本文件路径） calib/sample_000.bin calib/sample_001.bin ... （LLM 路线则直接给一个 prompts.txt，每行一句真实问题）
面试加分点：「校准集不是随便凑几百条，要匹配线上输入分布，长短和任务类型都覆盖，否则 outlier 会把某些层 scale 撑大、整层精度塌。」

讲解4. 板书④：量化前后精度怎么比（PPL + 人肉）

架构师不看「感觉变笨了」，要看数字。语言模型最通用的是困惑度 PPL：模型对下一 token 有多「困惑」，越低越好。

PPL = exp( −(1/N) · Σ ln p(wᵢ) )

先看手算，再套到量化对比上：

手算：5 个 token 的概率 p = [0.8, 0.6, 0.9, 0.5, 0.7] ln p = [-0.2231, -0.5108, -0.1054, -0.6931, -0.3567] Σ ln p = -1.8891 平均负对数似然 = 1.8891 / 5 = 0.3778 PPL = exp(0.3778) = 1.459 量化后同位置概率变成 p' = [0.7, 0.5, 0.8, 0.4, 0.6] Σ ln p' = -2.7001 → 平均 = 0.5400 PPL' = exp(0.5400) = 1.716 ΔPPL = 1.716 − 1.459 = 0.257 → 相对 +17.6% 经验判据（语言模型）： PPL 涨幅 < 5% → 放心上线 5% ~ 10% → 抽样人肉看，多半可接受 > 10% → 危险，换 w8a16 或调校准集

人肉对比（PPL 之外的必做项）：固定 20 个真实问题，原始模型和量化模型各答一遍，记录「是否跑题 / 是否重复 / 是否截断 / 是否答对」。表格存档，这是给产品经理看的东西。

人肉对比记录表（模板） # | 问题 | 原始质量(1-5) | 量化质量(1-5) | 现象 ---|-------------|--------------|--------------|---------------- 1 | 北京天气？ | 5 | 5 | 一致 2 | 算 17×23 | 5 | 3 | 量化后算错 3 | 写首五言诗 | 4 | 4 | 少一句 ... 统计：平均分差 > 0.5 或出现"事实错误"≥2 条 → 不能上线。

讲解5. 板书⑤：三个调优旋钮 + 带宽利用率

精度/速度不达标时，按下面顺序调。别瞎改，一次动一个变量。

旋钮一览（按性价比排序） ① group_size（int4 专用） 常见 32 / 64 / 128 小 → 组内更精细、精度更高，但 scale 开销↑ 128 是默认甜点（回顾第 2 章：开销仅 ~3%） ② 校准数据 换更贴近线上、覆盖更全的样本 性价比最高的一招，往往比调算法管用 ③ NPU 核心数 num_npu_core 3576 是单核 6 TOPS（3588 才三核）； 3576 上固定 1，调它没意义；迁 3588 时才有 1/2/3 可选 带宽利用率（判断跑没跑满的关键指标） decode 实测 8 tok/s，模型 int4 3B ≈ 2.0 GB 有效带宽 = 8 × 2.0 = 16 GB/s 利用率 = 16 / 35 = 45.7% → < 60% 说明没跑满，还有调优空间（batch/算子）
一句话记住：带宽利用率 = tok/s × 模型真实GB ÷ 35。它是判断「瓶颈在带宽还是在别处」的尺子，比单纯看 tok/s 有用得多。

讲解6. 板书⑥：上线判断（本章结论）

能不能上线？三关过完才敢点头 ① 精度关 PPL 涨幅 <5% 且人肉对比无事实错误 ② 性能关 tok/s 达产品延迟目标（如 > 8 tok/s） 且带宽利用率 ≥ 60%（说明已榨干带宽） ③ 稳定关 连续对话 30 分钟不 OOM、不崩、显存/内存平稳 三关全过 → 可以上线 任一不过 → 回退方案：w4a16 → w8a16，或换校准集重转 被问「这个量化方案能不能上线」→ 标准答： 「我按三关判：PPL 涨幅、人肉对比、带宽利用率与稳定性。 3B w4a16 若 PPL 涨幅 <5%、实测 >8 tok/s、利用率 ≥60%、长跑不 OOM、 人肉无事实错误——就上线；否则退 w8a16 或补校准集重转。」

RK3576 特别提示

  • RK3576 的 NPU 是 单核 6 TOPS，num_npu_core 固定为 1；「试核心数」是 RK3588 三核才有的玩法，3576 上调它没意义。
  • 3576 以 int8 定点加速为主，w4a16 多为 int8 模拟或部分算子支持——转完务必实测 tok/s 和精度，别想当然。
  • LLM 走 rknn-llm（rkllm） 一键转换，比手搓 ONNX 稳；小模型/ViT 才用 rknn-toolkit2。
  • target_platform 必须写 rk3576；换板子要重转，产物不通用。
