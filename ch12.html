课堂讲义（板书）

讲解0. 这节课到底学什么

前面几章处理的是图像（CV）和语音——都是「重」模态，要 NPU、要几百 MB 到几 GB 的内存。传感器时序信号完全相反：它是一维的、采样率低、模型极小，小到可以在一颗 MCU 上常年在线、用 mW 级功耗运行。这一章要建立这种「轻量常驻」的工程直觉。

本章的深度定位：你不需要训练大型时序模型，重点是会设计一条链路——怎么滑窗、怎么预处理、选什么网络、怎么部署到 TFLite-Micro / CMSIS-NN / RKNN、看什么指标、为什么必须考虑 QAT。

讲解1. 板书①：传感器时序任务

四类典型传感器时序任务 ① IMU 姿态 / 动作识别 加速度计 + 陀螺仪（各 3 轴）→ 手势、步态、跌倒、运动模式 ② 振动 / 异常检测 机械振动波形 → 轴承故障、异响、设备健康（正常 vs 异常） ③ 雷达（mmWave） 人体存在、呼吸、手势；非接触、保护隐私 ④ 心电 / 生理信号（ECG / PPG） 心率、心律异常、睡眠分期、疲劳监测 共性（记住这一句）： 它们都是一维时间序列——既不是图像的二维空间， 也不是文本的离散符号，而是"随时间的连续信号"。 → 所以预处理、网络选型、指标都和 CV/NLP 不一样。

讲解2. 板书②：代表网络

记住「名字 + 干什么 + 什么时候用」，不推结构。

时序识别的五类网络 1D-CNN ：在时间轴上滑卷积核，抽局部波形特征。 轻、快、端侧首选。适合固定窗口的动作识别。 TCN ：时间卷积（因果卷积 + 膨胀卷积）。 感受野大、可并行；适合较长序列、需要因果的场景。 LSTM / GRU ：循环网络，天然带"记忆"；比 1D-CNN 重，长序列慢。 小 Transformer：自注意力建长依赖强；端侧要用小版本 + 量化。 自编码器 AE：异常检测专用——只用"正常"数据训练， 重建误差大就判异常。 选型直觉（背下来）： 短窗口动作识别 → 1D-CNN（或 TC-ResNet 式轻卷积） 较长时序 / 要因果 → TCN / LSTM 异常检测 / 缺标注 → 自编码器（只喂正常样本） 端侧默认从 1D-CNN 起步：最小、最好量化、最好落地。

讲解3. 板书③：预处理

时序的成败有一半在预处理。四步：滑窗、滤波、归一化、特征工程。

① 滑窗切分（把长序列切成固定长度样本） 参数：窗口长度 window + 步长 stride（stride < window 则有重叠） 手算：IMU 50Hz，窗 2s = 100 点，步长 1s 60s 数据 → 窗口数 = (60 − 2) / 1 + 1 = 59 个 重叠的作用：一是不漏掉动作边界，二是数据增强。 ② 滤波 低通去高频噪声；带通保留关心频段（呼吸、振动、心电各自不同） 设计要点：截止频率要结合采样率（奈奎斯特）与实际信号频段。 ③ 归一化 均值-方差标准化或 min-max；按通道分别做； 用训练集统计量，固定下来在推理时复用（关键，别线上重算）。 ④ 特征工程（可选，仍很有效） 时域：均值、方差、峰峰值、过零率、RMS 频域：FFT 主频、频带能量、谱熵 端侧：小模型可直接吃原始波形；特征工程能进一步省算力。

讲解4. 板书④：模型极小、要常驻低功耗

体量：小到不可思议 1D-CNN 约 10K~50K 参数，int8 后 ≈ 10~50 KB → 可常驻 SRAM，MCU（无 OS）上也能常年在线 功耗：目标是 mW 级 MCU 推理 ≈ 1~10 mW 级（远低于 NPU 跑大模型） 传感器本体常在 µA~mW 级 整条链路目标：< 10 mW → 纽扣电池能跑数天到数周 设计原则：阶梯式（和语音 KWS 思路一致） 常驻"轻"模型做初筛 → 命中事件再唤醒"重"处理 / 上云 平时几乎不耗电，只在关键时刻动大算力。
平均功耗 = 常驻功耗 × 占比 + 唤醒功耗 × 占比

讲解5. 板书⑤：端侧框架

三个常用框架 TFLite-Micro ：专为 MCU 设计，无 OS、无动态内存分配， 运行时仅 KB 级 → 低功耗常驻首选。 CMSIS-NN ：ARM Cortex-M 的算子加速库， 配合 TFLite-Micro 提升卷积/矩阵运算效率。 RKNN ：上到有 NPU 的 RK 系列 SoC 时使用，能跑更大模型。 怎么选： MCU（电池供电、常驻、极低功耗）→ TFLite-Micro + CMSIS-NN SoC（有 NPU、多模态融合） → RKNN 同一套模型（如 1D-CNN）可在两者间转换，按硬件能力落地。

讲解6. 板书⑥：评估指标

分任务看指标 分类（动作识别）： Accuracy：只适合类别均衡 F1 = 2·P·R / (P + R) ← 类别不均衡首选 Precision / Recall 各自看"误判 vs 漏判" 回归（姿态角度）： MAE 平均绝对误差；RMSE 均方根误差（对大误差更敏感） 异常检测： 误报率 FPR（正常被报成异常）——"虚惊一场" 漏报率 FNR（异常被放过）——"漏网之鱼" 综合看 F1 / AUC 手算 1（RMSE）：误差 = [1, 2, -1] MSE = (1² + 2² + (−1)²) / 3 = 6 / 3 = 2 RMSE = √2 ≈ 1.41 手算 2（F1）：P = 0.9，R = 0.8 F1 = 2 × 0.9 × 0.8 / (0.9 + 0.8) = 1.44 / 1.7 ≈ 0.847

讲解7. 板书⑦：量化敏感点

三个敏感点（务必记住） ① 小模型对量化更敏感 参数少 → 单个权重的量化误差占比就大 → int8 PTQ 掉点明显。 对策：QAT（量化感知训练）——让小模型在训练中 主动适应量化误差，这是 sensor 链路的常见必要条件。 ② 对噪声 / 漂移敏感 传感器安装位置、个体差异、温漂 → 输入分布漂移。 → 训练 / 校准集要覆盖不同设备、不同工况、不同人。 ③ 归一化统计量要一致 量化前用训练集的 mean/std；转换/推理时保持一致， 别用线上重算的统计量（会引入分布错位）。 一句话：sensor 量化，往往"PTQ 不够、要靠 QAT"—— 这与小 KWS 模型同源：模型越小，越难 quantize。

本节要点回顾

  • 传感器时序信号是「一维、低采样率、模型极小」的一类端侧模态，与 CV/语音的工程直觉相反。
  • 四类典型任务：IMU 姿态/动作识别、振动异常检测、雷达感知、心电/生理信号。
  • 代表网络：1D-CNN（首选）、TCN、LSTM/GRU、小 Transformer；异常检测常用自编码器。
  • 预处理四步是滑窗切分、滤波、按通道归一化、可选特征工程；归一化统计量要固定复用。
  • 模型仅 10~50 KB、推理 1~10 mW 级，可常驻 MCU；设计用「常驻轻模型 + 事件唤醒」的阶梯式。
  • 部署框架：MCU 用 TFLite-Micro + CMSIS-NN，SoC 用 RKNN。
  • 评估上分类看 F1、回归看 MAE/RMSE、异常检测看 FPR/FNR + F1。
  • 量化敏感点：小模型对量化更敏感（常需 QAT）、对噪声/漂移敏感（校准集要覆盖多工况）。

RK3576 特别提示

  • 传感器模型极小，若追求极致低功耗常驻（电池供电），优先 TFLite-Micro + CMSIS-NN 上 MCU。
  • 若要在 3576 这种带 NPU 的 SoC 上做多模态融合（语音/视觉/传感器一起），则用 RKNN 把 1D-CNN 一并落地在 NPU。
  • 小模型对量化更敏感：int8 PTQ 掉点明显时，优先补校准集覆盖多工况，必要时上 QAT。
  • 温漂、个体差异、安装位置都会让输入分布漂移——训练/校准集要覆盖不同设备与工况，否则线上掉点。
  • 归一化统计量（mean/std）要与训练一致并在推理时固定复用；线上重算统计量会引入分布错位。
  • 功耗是硬指标：用「常驻功耗 × 占比 + 唤醒功耗 × 占比」做预算，目标整链路 < 10 mW。
