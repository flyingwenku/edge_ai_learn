附录 A：端侧表征复用与决策头

一句话：不生成文字，只跑 prefill 取最后一层 hidden state，用 896 维向量直接做决策——单次 161~316 ms，比让 0.5B 自由生成快一个量级，而且可复现。这是「LLM 当编码器用」的一条实测支线。

状态：实测 POC · 2026-10-15 平台：RK3576 / rkllm 1.2.3 模型：Qwen2.5-0.5B W8A8
本页口径： 理论hidden state 的含义、线性探针、温度校准与 ECE 属通用方法。 实测所有数字来自本板 POC：hidden 维度/时延/可复现性/真假日相关/校准前后兜底率。 偏差原文档里两处写法已修正——「零训练点积换选项」不成立、「置信度可当可靠性」不成立。

一、为什么值得做

延迟
161~316 ms

纯 prefill，无 decode；自回归生成 20 token 约 1 s

向量维度
896

与 Qwen2.5-0.5B hidden size 完全一致

可复现
md5 一致

同 prompt 两次导出完全相同

端侧小模型的自由生成不可靠（第 16 章已用实验证明：0.5B 在决策任务上是常数输出）。但它的表征仍可能有用：把模型当编码器，只做一次前向，把 hidden 交给一个几十 KB 的线性头。这条路把「生成的不确定性」换成了「分类的可度量性」。

二、接口能力（RKLLM 原生，不用改 SDK）

rkllm.h 里的三种推理模式 RKLLM_INFER_GENERATE = 0 ← 正常生成 RKLLM_INFER_GET_LAST_HIDDEN_LAYER = 1 ← 决策头要的 RKLLM_INFER_GET_LOGITS = 2 ← 温度校准要的 typedef struct { const float* hidden_states; // num_tokens × embd_size int embd_size; int num_tokens; } RKLLMResultLastHiddenLayer;
配套能力齐全：rkllm_set_chat_template() 自定义模板 · RKLLM_INPUT_TOKEN 直接喂 token id 精确定位 · rkllm_load_lora() · rkllm_clear_kv_cache()。

偏差更正 1：原以为「hidden 依赖运行时状态、不可复现」。实测 md5 完全一致——所以 「板端导出 hidden → 回传 PC 训头 → 部署回板」这条闭环成立，训练与推理看到的是同一个东西。

四、三条硬约束（踩过才知道）

① 指针只在本次 callback 内有效 SDK 注释：需要在当前 callback 中获取，若未及时获取，下一次 callback 会释放该指针。 → 必须立刻 memcpy 出来，不能存指针。 ② 绝对不能用原始余弦相似度当决策 状态A（离线/12%/41℃） l2=306.515 状态B（在线/95%/25℃） l2=305.877 cos(A, B) = 0.9558 ← 两个完全不同的状态，相似度仍极高 ③ 必须用板端量化后的 hidden 训练 W8A8 会改变 hidden 分布；用 PC fp32 hidden 训完搬上板，头会失效。

为什么 cos 这么高：小模型 hidden 有强各向异性——所有句子共享一个很大的公共分量。直接比相似度等于在比公共分量，判别信息被淹没。必须训一个线性头，把判别方向从公共分量里分离出来。

五、真相关 vs 假相关（证明 hidden 里真有信息）

同一类状态（天气预报）问两个问题：带伞（标签由状态决定，真相关）与带钥匙（标签随机，假相关）。240 条样本，板端批量导出 hidden，PC 上训 Linear(896, 2)。

七、三种决策头对比（「专用模型」质疑的答案）

模板改成运行时注入选项：[STATE]… [QUESTION] action in {带伞, 不带伞} [OPTIONS] 带伞 不带伞。两个完全不同的选项集（带具 / 出行方式）共用同一批状态。

头形式参数量选项集 A选项集 B换选项的代价
H1 固定 LinearLinear(896, n)n×8961.0001.000改架构重训
H2 零训练点积q·o/√d00.5450.455换缓存表
H3 只训选项向量只训 o_vecn×8960.8910.964重训几秒
结论：文档设想的「零训练换选项」（H2）在 0.5B + W8A8 上不成立（0.545/0.455 ≈ 瞎猜）， 原因就是 0.956 的各向异性。现实路径是 H3：底座冻结、只训 n×896 个选项向量，换任务几秒钟； 「专用」的部分只有这几千个参数，和「每个任务训一个专用模型」有数量级差别。

八、一次 prefill 取多个向量

用 token 模式精确定位（n_tokens 与请求 id 严格 1:1） mp_2.txt (2 选项) pos=41,45,48 -> n_tokens=49 / 请求 49, rows=3 (1 q + 2 o) mp_3.txt (3 选项) pos=39,42,45,49 -> n_tokens=50 / 请求 50, rows=4 (1 q + 3 o) 实测时延 q_vec（含 [QUESTION]，41.2 tokens） 161.2 ms o_vec（独立选项，13.8 tokens） 89.6 ms ← 只在离线算一次，运行时查表 端到端单次决策 229 ms（48.7 tokens）
坑：token 模式不能在同一进程里跑第二次。第二次起 num_tokens 会失真（20→10、30→10、49→46）； 改成「每个 prompt 一个独立进程」就完全正确（10→10、20→20、50→50）。prompt 模式没有这个问题，可正常批量。 结论：批量导出用 prompt 模式，需要精确定位时用 token 模式 + 独立进程。

九、落地七步

① 定义任务：先锁一个窄域决策，选项固定且可枚举 ② 造数据：每条样本 = [STATE] + [QUESTION] + 硬标签 ③ 板端批量导出 hidden（prompt 模式，240 条约 35s） ④ PC 训头：Linear(896, n) + CE；选项向量版（H3）只训 o_vec ⑤ 蒸馏：用强模型打软标签做 KL——对 0.5B 这步不能省 ⑥ 温度校准：dev 集网格搜 T，写死进板端 C 代码 ⑦ 低置信兜底：confidence < 0.4~0.6 走规则或云端 部署形态：运行时只有一次 161~229 ms 的 prefill + 一次矩阵乘；o_vec 是离线常量表

十、边界认知（别把 POC 当产品）

学到的是浅层规则

训练集只有「降雨概率高→带伞」，头就只学会这一条。遇到「90% 但全天不出门」「开车从地库到地库」全部判错且置信度 1.000。这是数据覆盖问题，不是方法问题。

温度校准抓不住 OOD

股市行情、冰箱内容这类无关输入，置信度 0.987 / 0.999，兜底不触发。校准只修正分布内过度自信，不能替代 OOD 检测——要另加领域标识或「可判否」头。

17 条边界用例：9 对 / 5 错

准确率 0.643。亮点是跨语言（英文天气判对）、抗干扰（长通知里抓降雨）、泛化（「早上晴傍晚转雨」训练集没有也能判对）。

底座坏了，头救不回来

W4A16 有稳定语义退化（连「鸡有几个头」都答错），表征空间已被污染。这个场景必须用 W8A8。

十一、作业与验收

1

跑通 hidden 探针

目标
板端导出一条 896 维向量，并验证两次 md5 一致。
要掌握
GET_LAST_HIDDEN_LAYER 模式；callback 内 memcpy；num_tokens 的含义。
检验标准
embd_size=896；两次导出 md5 相同；能解释「为什么必须立刻拷贝」。
2

训一个头并做真假相关对照

目标
真相关任务测试 ≥0.9；假相关任务测试接近随机。
要掌握
为什么不能用 cos 直接判；为什么必须用板端量化 hidden。
检验标准
两张准确率表 + 一句「假相关学不到」的机制解释。
3

温度校准与兜底

目标
dev 集搜 T，报出校准前后 ECE 与兜底触发率。
要掌握
ECE 的含义；为什么校准只对「在瞎猜」的场景有效。
检验标准
能说清「不校准，兜底形同虚设」，并给出一个具体触发率对比。

本节要点回顾

要点回顾
  • LLM 可以只当编码器：一次 prefill 取 hidden，161~316 ms，比自回归生成快一个量级。
  • hidden 是确定性的（md5 一致），所以「板端导出 → PC 训头 → 回板部署」闭环成立。
  • 不能用原始余弦相似度决策：不同状态 cos=0.956，小模型各向异性极强，必须训判别头。
  • 必须用板端量化后的 hidden 训练，PC fp32 训完搬过去会失效。
  • 置信度不可信：答错时 0.877 > 答对时 0.813；温度校准把兜底触发率从 4.2% 提到 75%。
  • 零训练点积换选项在 0.5B 上不成立（0.545/0.455）；现实路径是只训选项向量（0.891/0.964）。
  • token 模式同进程第二次会失真，批量用 prompt 模式、精确定位用 token 模式 + 独立进程。
  • 校准抓不住 OOD；浅层规则不等于语义理解——POC 到产品之间还差数据覆盖与 OOD 检测。
