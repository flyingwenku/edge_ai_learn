课堂讲义（板书）

讲解0. 这节课到底学什么

一句话：把「模型多大、占多少内存、跑多快」变成你能心算的常识。

你是架构师，选型时老板/面试官不会给你跑一遍再决定。你需要在买板子之前就说出：这个 3B 模型能不能塞进 3576、能跑多快、值不值得。这节课就是练这个。

讲解1. 什么是量化（Quantization）

模型里每个「参数」本来用 32 位小数（float32）存。量化就是用更少的位去存它：32 位 → 8 位 → 4 位。

类比：一张高清照片（fp32）压成小图（int4），文件小很多、传得快，但细节会糊一点。

量化带来的变化： 位数 ↓ → 内存 ↓ → 带宽需求 ↓ → 速度 ↑ 代价：精度 ↓（答得没那么准） 架构师的口诀：「能用低精度，就别用高精度」—— 只要效果掉得可接受，int4 永远优先于 fp16。

讲解2. 板书①：位数 → 字节

只需要一条换算：1 Byte = 8 bit。把「每个参数多少位」除以 8 就是字节数。

精度 位数 ÷8 每参数字节 ───────────────────────────────────────────── fp32 32 bit → 32/8 = 4.0 Byte fp16 16 bit → 16/8 = 2.0 Byte bf16 16 bit → 16/8 = 2.0 Byte int8 8 bit → 8/8 = 1.0 Byte int4 4 bit → 4/8 = 0.5 Byte ← 关键 int4 = 0.5 字节：因为 4 位装不下 1 个字节， 所以硬件把 2 个参数打包进 1 个字节（叫 packed）。 这就是为什么「4 位」听起来像省了一半，其实是省到 1/8。
bf16 vs fp16（只记结论，不推公式）：字节数一样（都是 2B）。fp16 精度细但范围窄、容易溢出；bf16 范围大、更稳，现代大模型/端侧更偏好 bf16。你选型时默认 bf16 就对了。

讲解3. 板书②：内存公式 + 手算示范

权重内存 ≈ 参数量 × 每参数字节

注意「≈」，因为真实占用总比净值大一点（下面解释）。先看一个完整手算：

示范：3B 模型放 int4 要多少内存？ 第一步 净值： 3,000,000,000 个参数 × 0.5 Byte = 1,500,000,000 Byte = 1.5 GB（净权重） 第二步 真实： ×1.2 ~ 1.4 的 overhead ≈ 1.5 × 1.3 = 约 2 GB ← 这就是「3B int4 约 2GB」的来历 为什么有 overhead？ ① Embedding 表通常不量化（或单独 int8），体积不小 ② LayerNorm / bias 这类小张量一般留高精度 ③ 内存对齐、runtime 缓冲、框架自身开销 经验值：int4 真实占用 ≈ 净值 × 1.3，工程上直接取整背整数。

讲解4. 板书③：带宽 → 理论 tok/s

这是本章的灵魂。大模型生成文字时（decode），每吐 1 个 token，NPU 都要把整个模型权重从内存里读一遍。所以速度不由算力决定，由内存带宽决定。

理论 tok/s ≈ 内存带宽 ÷ 模型真实占用(GB)
示范（RK3576，带宽 35 GB/s） 3B int4： 35 ÷ 2.0 = 17.5 ≈ 17 tok/s （理论天花板） 7B int4： 35 ÷ 4.0 = 8.75 ≈ 8.75 tok/s （理论天花板） 为什么实测只有 5~10 tok/s，远低于理论？ ① 有效带宽达不到峰值，通常打 6~8 折 ② KV Cache 也在抢带宽（第 5 章细讲） ③ kernel 调度、算子切换有开销 ④ 有些算子没跑到 NPU，掉回 CPU
一句话记住：算力决定「能不能算」，带宽决定「算多快」。LLM 聊天场景默认是带宽瓶颈——这句话后面每章都用得上。

讲解5. 板书④：量化数学（下午写脚本用）

对称量化就三步，把它想成「找一把尺子，把所有数对齐到刻度上」：

给定一批数字 x，量化到 int8： qmax = 127 # 8 位有符号最大整数 scale = max(|x|) / qmax # 这把尺子的刻度 q = round(x / scale) # 量化：小数 → 整数 x' = q * scale # 反量化：整数 → 近似小数 举例 x = [-1.2, 0.5, 3.0] max(|x|) = 3.0 → scale = 3.0/127 ≈ 0.0236 q = round([-50.8, 21.2, 127]) = [-51, 21, 127] x' = [-1.204, 0.496, 3.0] 误差 = [-0.004, -0.004, 0] ← 很小，因为 8 位刻度够细 换成 int4（qmax=7）：刻度变粗 → 误差明显变大 scale = 3.0/7 ≈ 0.4286 → x' = [-1.29, 0.43, 3.0] int4 误差 ≫ int8 误差 ← 这就是低精度的代价

RK3576 特别提示

  • 带宽 35GB/s 是理论峰值，实际有效带宽通常打 6~8 折，所以「理论 17 tok/s、实测 5~10」是正常的。
  • 16GB 内存不代表能装大模型——留给系统、KV Cache、多进程的空间要扣掉，实际安全预算约 8~12GB。
  • 3576 的 NPU 是 6 TOPS int8；int4 通常靠 int8 模拟或特定算子支持，第 9 章验证，本章先按理论算。
