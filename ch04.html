课堂讲义（板书）

讲解0. 这节课到底学什么

第 3 章你把 Transformer 拆成了层。这一章啃最硬的那块骨头——注意力（Attention）。架构师不需要会推导公式，但必须能做到两件事：① 用一句人话解释 Q/K/V 在干什么；② 拿到 config 秒算 KV Cache，说清为什么端侧偏爱 GQA。这两条直接对应面试题。

讲解1. 板书①：Q、K、V 的物理含义

别被字母吓到。把注意力想成一次「查字典」：

Q / K / V = 提问 / 索引 / 内容 Q (Query) = 你要查的"问题" → 当前 token 在问："谁跟我相关？" K (Key) = 字典的"索引/标签" → 每个 token 举牌："我是关于什么的" V (Value) = 字典的"释义/内容" → 每个 token 真正携带的信息 计算三步（这就是注意力）： ① 拿 Q 去比每一个 K → 算相似度分数 s = Q·K ② softmax 把分数变成权重 → 权重和为 1，越大越"被关注" ③ 按权重把 V 加权求和 → 输出 = 相关 token 内容的加权平均 一句话：Q 决定"看哪里"，K 决定"被谁看到"，V 是"被取走的内容"。
记住：注意力 = 按相关度，从所有 token 的 V 里"加权取货"。它不是"筛选"，而是"加权平均"——所有 token 都会贡献一点，只是相关的高、不相关的低。

讲解2. 板书②：注意力公式的直觉 + 手算

公式只有一个（不用推，看它每一步在干嘛）：

Attention(Q, K, V) = softmax( QKᵀ / √dk ) · V
四步拆解（对着公式看物理含义） ① QKᵀ → 每个 query 和每个 key 点积 = 相似度矩阵 (n×n) ② /√d_k → 缩放，防止点积随维度变大而"爆炸"（下面单独讲） ③ softmax → 每行归一化成权重（该 query 看各 token 的比例） ④ ×V → 按权重对 V 做加权求和 手算示范：1 个 head，d_k=4，序列长度 n=3 q = [1, 0, 1, 0] K = [ k1=[1,0,1,0] k2=[0,1,0,1] k3=[1,1,0,0] ] ① 相似度 s = q·k s1 = 1·1 + 0·0 + 1·1 + 0·0 = 2 s2 = 1·0 + 0·1 + 1·0 + 0·1 = 0 s3 = 1·1 + 0·1 + 1·0 + 0·0 = 1 s = [2, 0, 1] ② 缩放：/ √d_k = / √4 = / 2 s' = [1.0, 0.0, 0.5] ③ softmax（e^1=2.718, e^0=1, e^0.5=1.649；和 = 5.367） w = [0.507, 0.186, 0.307] ← 权重和 = 1 ✅ ④ 加权 V（设 v1=[1,0], v2=[0,1], v3=[1,1]） out = 0.507·[1,0] + 0.186·[0,1] + 0.307·[1,1] = [0.507+0.307, 0.186+0.307] = [0.814, 0.493] 物理直觉：输出 = "按相关度加权平均后的 V"。相关度高的 token 占比大。

再单独把「为什么除以 √dk」讲透——这是面试常问的细节：

为什么要 /√d_k ？看两种情形 不缩放：s = [2, 0, 1] → softmax → [0.665, 0.090, 0.245] （更尖锐） 缩放：s'= [1, 0, 0.5] → softmax → [0.507, 0.186, 0.307] （更平滑） 原因：维度 d 越大，点积 q·k 的方差越大 → 分数差距被拉大 → softmax 趋于 one-hot（[1,0,0,...]） → 梯度趋近 0，模型"学不动"。 除以 √d_k 把方差压回 1 量级，softmax 保持"温和"。 一句结论：√d_k 是为了防止 softmax 饱和（防止梯度消失）。
架构师记这句就够：Q 查、K 被查、V 取货；softmax 是"加权平均"，√dk 是"防止权重两极化"。

讲解3. 板书③：MHA → MQA → GQA → MLA

这四个是注意力的四种「共享 K/V 的方式」，演进目标只有一个：压缩 KV Cache。

方案KV 份数KV Cache质量NPU/端侧友好
MHA 多头注意力= Q 头数（每头独立）最大最好一般（太占带宽）
MQA 多查询1（所有 Q 头共享 1 组）最小略降好
GQA 分组查询G 组（如 2、4、8）小≈ MHA最好（端侧甜点）
MLA 潜在注意力压成低维 latent 向量极小≈/优于 MHA复杂，NPU 不直接支持
用人话记住四个演进台阶 MHA：32 个 Q 头 → 32 组 K/V（最贵，最准） MQA：32 个 Q 头 → 1 组 K/V（最省，但质量掉） GQA：32 个 Q 头 → 8 组 K/V（每组被 4 个 Q 头共享）← 折中 MLA：把 K/V 压缩成一个低维向量再还原（DeepSeek 用它，省到极致） GQA 的核心：多个 Q 头"共用"一组 K/V，KV 份数直接从 heads 降到 G。 质量损失很小（因为相邻头本来就有冗余），但 KV Cache 直接砍几倍。
记忆锚点：MHA→MQA 是"一刀切共享"，GQA 是"分组共享"。GQA 用很小的质量代价，换回接近 MQA 的内存/带宽收益——这就是它能成为行业默认（Qwen、Llama、Gemma 全用）的原因。

讲解4. 板书④：为什么 RK3576 偏爱 GQA（带宽手算）

这是本章的核心算账。用 Qwen2.5-3B 的真实 config 来算，你可以跟着手写：

模型 config（Qwen2.5-3B 近似） hidden d = 2048 heads = 16 （Q 头数） head_dim = 128 layers L = 36 KV 精度 = fp16（2 字节） 每 token 的 KV Cache 公式 KV/token = 2（K和V）× kv_heads × head_dim × 2字节 × L 三种方案的 kv_heads MHA：kv_heads = 16 GQA：kv_heads = 2 MQA：kv_heads = 1
手算：每 token KV Cache MHA: 2×16×128×2×36 = 294,912 B ≈ 288 KB GQA: 2× 2×128×2×36 = 36,864 B ≈ 36 KB → 是 MHA 的 1/8 MQA: 2× 1×128×2×36 = 18,432 B ≈ 18 KB 换算成 8K 上下文（8192 token） MHA: 288 KB × 8192 ≈ 2.42 GB GQA: 36 KB × 8192 ≈ 0.30 GB（302 MB） MQA: 18 KB × 8192 ≈ 0.15 GB（151 MB） 再算"每生成 1 个 token 要读多少 KV"（NPU 独占 12~16 GB/s） MHA: 2.42 GB / 12~16 = 151~202 ms GQA: 0.30 GB / 12~16 = 19~25 ms MQA: 0.15 GB / 12~16 = 9~13 ms 加上权重（3B int4 ≈ 2.0 GB → 2.0/12~16 ≈ 125~167 ms） GQA 总耗时 ≈ 144~192 ms → ≈ 5.2~6.9 tok/s MHA 总耗时 ≈ 276~369 ms → ≈ 2.7~3.6 tok/s 结论：8K 上下文下，GQA 相对 MHA 把吞吐拉回约 2 倍。 产品真实场景带宽只有 7~11 GB/s，这些数字还会再掉一档。
RK3576 偏爱 GQA 的真正原因：decode 阶段是带宽瓶颈，每生成一个 token 都要把整段 KV Cache 从内存读一遍。3576 的带宽三档里最大的理论峰值也只有 19 GB/s，产品场景实际只有 7~11 GB/s（NPU 独占 12~16），MHA 的长上下文 KV 会直接把带宽吃光；GQA 把 KV 砍到 1/8，等于给带宽"续命"。GQA 省的不是存储，是每 token 的读取带宽。

讲解5. 板书⑤：位置编码速览（含 RoPE 直觉）

注意力本身是「无序」的——它只算点积，不知道谁在前谁在后。所以必须额外把位置喂进去。

三种位置编码速览 ① 绝对位置编码（Learned / 正弦） 做法：把"位置向量"直接加到 token embedding 上 x = tok_emb + pos_emb 优点：直观、简单 缺点：长度写死（超过训练长度就"瞎"），外推差 ② 相对位置编码（T5 bias / ALiBi） 做法：只编码"两个 token 之间的距离"，不管绝对位置 优点：天生外推好 缺点：实现各异、生态不统一，逐步被 RoPE 取代 ③ RoPE 旋转位置编码 ← 现在主流（Qwen / Gemma / MiniCPM 全用） 做法：不"加"位置，而是把 Q、K 向量按位置旋转一个角度
RoPE 怎么编码位置（看直觉，不推公式） 把 q、k 的每一对维度看成一个 2D 向量 [x, y]。 位置 m 的 token，其向量旋转 m·θ；位置 n 旋转 n·θ。 关键性质： 旋转后 q_m · 旋转后 k_n = cos( (m-n)·θ ) · |q||k| → 点积只和相对位置 (m-n) 有关！ 举例：q = [1,0] 位置 0 旋转 0° → [1, 0] 位置 1 旋转 45° → [0.707, 0.707] 点积随距离变化： m-n = 0 → cos0 = 1.0 （同位置，最相关） m-n 变大 → 点积变小 （离得越远越不相关） 就这么简单：RoPE 用"旋转角度差"来感知"位置差"。没有额外参数，天然带相对位置信息。
长度外推：为什么 RoPE 能外推、又为什么还要微调 - RoPE 天然能外推：θ 频率固定，训练 4K 也能"算出" 8K 的角度 - 但高频维度在长位置"转太快"，模型没见过 → 效果退化 - 常见外推技巧（只需知道名字和作用）： · 位置插值 (PI)：把 8K 位置压缩回 4K 范围再用 · NTK-aware / YaRN：调大 θ 基准（如 10000 → 500000），拉长可用范围 · 长上下文微调：继续训练，最稳 架构师结论：选模型先看它的 max_position_embeddings 和是否做过 YaRN/NTK 外推。 别自己"硬拉"上下文长度——超标会静默变傻。
记住三点：RoPE 用旋转编码相对位置；无额外参数、外推友好；要做长上下文，看模型有没有做 NTK/YaRN 外推。

RK3576 特别提示

  • 3576 的瓶颈是带宽（三档：峰值 19 / NPU 独占 12~16 / 产品 7~11 GB/s），不是算力。注意力层选型的第一标准永远是"KV Cache 省不省带宽"。
  • 优先选 GQA 模型（Qwen2.5、Gemma、MiniCPM 都是 GQA），MHA 长上下文会明显掉速。
  • MLA 省得更多，但 RKNN/NPU 不直接支持，端侧落地成本高；目前仍以 GQA 为甜点。
  • 做长上下文方案时，先确认模型的 max_position_embeddings，不要盲目拉长——超标会静默"变傻"。
