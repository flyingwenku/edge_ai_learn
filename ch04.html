课堂讲义（板书）

讲解0. 这节课到底学什么

第 3 章你知道 decode 是「逐 token 生成」。但每生成一个 token，模型要去看前面所有 token 的信息——如果每次重算，代价爆炸。KV Cache 就是为此而生，代价是内存随上下文线性增长。算得清它，你才算摸到端侧 LLM 的门槛。这一章的 KV Cache 和瓶颈定位，是面试的必问题。

一句话记住：KV Cache 是「时间换空间」；端侧跑 LLM，空间（带宽）往往比时间（算力）更致命。

讲解1. 板书①：KV Cache 为什么存在

Attention 的本质：新的 Query 要和前面所有 token 的 Key 做点积、再用结果去加权所有 Value。问题在于这些 K、V 每步都会用到。

没有 Cache 会怎样： 生成第 100 个 token 时，要把前 99 个 token 的 K、V 全部重算一遍； 生成第 101 个再重算前 100 个…… 计算量 ~ N² 爆炸。 有 Cache 之后： 每个 token 的 K、V 只算 一次，算完就存起来； 第 N 个 token 直接用缓存里的 [K1…K_{N-1}]，只算自己这份。 代价：省了算力，但要一块内存常驻 —— 这就是 KV Cache。 它随上下文长度线性增长，是端侧内存的头号变量。

讲解2. 板书②：KV Cache 公式 + 手算 Qwen2.5-3B

公式不长，但每个符号都要理解物理含义。别背，按「2 份 × 层 × 头 × 维度 × 长度 × 字节」念出来。

KV_bytes = 2 × layers × kv_heads × head_dim × seq_len × bytes
逐项物理含义： 2 = K 和 V 两份（各存一份） layers = 层数（每层都有自己的 K/V） kv_heads = KV 的头数（GQA 时 < Q 头数） head_dim = 每个头的维度 seq_len = 缓存了多长上下文（token 数） bytes = 每个数的字节：fp16 = 2，int8 = 1 Qwen2.5-3B 假设：layers = 36, kv_heads = 2, head_dim = 128, fp16 每 token = 2 × 36 × 2 × 128 × 2 = 2×36 = 72 = 72×2 = 144 = 144×128 = 18432 = 18432×2 = 36864 B ≈ 36 KB / token 长度换算（× token 数）： 1K = 36 KB × 1024 ≈ 36 MB 4K = 36 KB × 4096 ≈ 144 MB 8K = 36 KB × 8192 ≈ 288 MB
秒算口诀：「每 token 36 KB」——记住这个数，4K/8K 随口就来。

讲解3. 板书③：MHA → MQA → GQA → MLA 演进

为什么 KV 头数可以比 Q 头数少？因为KV 才是内存大头，业界想尽办法砍它。

四种注意力，砍的就是 KV 头数： 【MHA 多头注意力】Q/K/V 头数全部相等 = 16 每 token = 2×36×16×128×2 = 288 KB　← 最贵 表达力最强，但 KV Cache 最大 【MQA 多查询注意力】K/V 只有 1 个头，所有 Q 共享它 每 token = 2×36×1×128×2 = 18 KB　← 最省 省 16 倍，但精度掉得明显，大模型少用 【GQA 分组查询注意力】K/V 头数 = 2（16 个 Q 分成 8 组共享） 每 token = 2×36×2×128×2 = 36 KB　← 工业主流 Qwen2.5 / Llama3 都用它：省内存又保精度 【MLA 多头潜在注意力】DeepSeek：把 K/V 压成低维隐向量再存 比 GQA 更省，但结构复杂、NPU 不友好
面试点：「GQA 是 MHA 省内存、MQA 保精度的折中，Qwen2.5 用 GQA（K/V=2 头）。」

讲解4. 板书④：算力瓶颈 vs 带宽瓶颈（算术强度）

判断瓶颈不用跑测试，一个比值就够——算术强度。

算术强度 AI = 计算量(FLOPs) ÷ 访存量(Bytes)
判据： AI 大 → 每次搬数都能算很多次 → 算力瓶颈（compute-bound） AI 小 → 数据搬进来还没算几下就没了 → 带宽瓶颈（memory-bound） 机器的「脊点」= 峰值算力 ÷ 内存带宽： RK3576：6 TOPS int8 ÷ 35 GB/s = 6000 / 35 ≈ 171 FLOP / Byte 只要任务 AI < 171 → 判为带宽瓶颈 decode 的 AI 有多小？ 3B int4 权重 ≈ 2 GB，生成 1 token ≈ 2×3G = 6 GFLOP AI ≈ 6 GFLOP ÷ 2 GB = 3 FLOP / Byte 3 ≪ 171 → 严重带宽瓶颈 prefill 的 AI 呢？ 512 token 一次并行，权重读一次算一大片 → AI 高，偏算力瓶颈

讲解5. 板书⑤：为什么 RK3576 上是带宽瓶颈

三个数字摆一起，结论自动浮现。

三个数字： NPU 算力 6 TOPS int8 （很快，够用） 内存带宽 ≈ 35 GB/s （真正瓶颈） 模型 int4 3B ≈ 2 GB （每步都要整个读一遍） 理论天花板： decode 理论最高 = 35 GB/s ÷ 2 GB = 17.5 token/s 再扣掉读 KV Cache、算子开销、非理想访存 → 实测 5~10 tok/s 推论（重要）： 把 NPU 换成算力翻倍的芯片、但带宽不变 → decode 几乎不变 把模型从 int4 压更狠、或上 GQA/KV 量化 → decode 明显变快 结论：3576 上 LLM decode 的天花板由带宽决定，不是算力。 优化方向 = 「少读、少存」，不是「堆算力」。
一句话结论：带宽 35 GB/s ÷ 模型 2 GB ≈ 17 tok/s，这就是端侧 LLM 的物理上限。

讲解6. 板书⑥：瓶颈定位速查

现象 → 判定 → 对策 首字慢 / 长 prompt 卡 → prefill 偏算力 → 批处理、分块 prefill 出字慢 / 逐 token 卡 → decode 带宽瓶颈 → 量化、GQA、KV 量化 上下文越长越卡 → KV Cache 膨胀 → 缩短上下文、KV Cache 量化 换更强 NPU 却没用 → 说明卡在带宽 → 先查带宽，别急着换芯片 速算模板（背下来）： 1) KV / token = 2×L×kv_heads×d×bytes 2) 总量 = ×seq_len 3) 瓶颈 = 比较 AI 和脊点 (3576 ≈ 171)

面试话术

可直接背

「KV Cache 是为了避免 decode 时重算历史 K/V，公式是 2 乘层数乘 KV 头数乘 head_dim 乘序列长度乘字节数。以 Qwen2.5-3B 为例，36 层、GQA、KV 头数 2、head_dim 128，每 token 约 36 KB，8K 上下文大概 288 MB。判断瓶颈我用算术强度：计算量除以访存量。RK3576 的脊点是 6 TOPS 除以 35 GB/s 约等于 171，而 decode 每 token 只做 2×3G 的浮点运算却要读 2 GB 权重，算术强度约等于 3，远低于 171，所以 decode 是带宽瓶颈。理论天花板是 35 GB/s 除以 2 GB 约 17 token/s，实测 5 到 10。所以优化方向是量化、GQA、KV Cache 量化去少读少存，而不是堆算力。」

能力标签：能秒算 KV Cache、能定位算力/带宽瓶颈——内存测算与瓶颈诊断能力。

RK3576 特别提示

  • 3576 内存带宽约 35 GB/s，是 LLM decode 的硬天花板；算力 6 TOPS 反而不是瓶颈。
  • LPDDR5 双通道才能跑满带宽，工程上要注意内存颗粒与频率配置。
  • KV Cache 与模型权重抢同一块带宽，长上下文会同时拖慢 decode。
  • 端侧长上下文可考虑 KV Cache int8 量化（第 10 章展开），直接减半带宽压力。
