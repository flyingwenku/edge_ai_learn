课堂讲义（板书）

讲解0. 这节课到底学什么

第 1 章你学会了「模型多大」。但同样 int4，做法不同，精度能差一大截——差别就在量化粒度。搞懂粒度 + 三个主流方案，你就能回答面试官最爱问的那句：「这个 3B 模型你打算怎么量化、为什么？」

讲解1. 板书①：量化粒度三级

回顾：量化的关键是那把「尺子」——scale。粒度 = 一把尺子管多少个权重。

粒度三级（从粗到细） ① per-tensor 整个权重矩阵 共用 1 把尺子 scale 最少，精度最差 ② per-channel 每一行（每个输出通道）各用 1 把尺子 int8 的标配做法 ③ group-wise 每 group_size（常见 128）个权重 1 把尺子 int4 的标配做法；组越小组内越精细 一句话：尺子越细，精度越高，但要额外存 scale。 粒度本质是「精度 ↔ 存储开销」的权衡。

讲解2. 板书②：为什么 int4 必须 group-wise

核心矛盾：权重里有个别「离群点」（outlier）数值特别大。一把尺子若被 outlier 撑大，其他正常的权重就全被压到 0 附近，精度直接崩。看数字：

权重 W = [0.10, 0.15, -0.12, 0.09, 10.0] （最后一个是 outlier） int4 对称量化：qmax = 7，刻度只有 -7 ~ 7，共 15 档 【per-tensor】一把尺子 scale = max|W| / 7 = 10.0 / 7 = 1.4286 q = round(W / scale) = round([0.07, 0.105, -0.084, 0.063, 7]) = [0, 0, 0, 0, 7] ← 前 4 个全变 0 ！ W' = [0, 0, 0, 0, 10] 小权重信息 100% 丢失，模型废了 【group-wise，group_size=4】一组一把尺子 A 组 [0.10, 0.15, -0.12, 0.09]：scale = 0.15/7 = 0.02143 q = [5, 7, -6, 4] → W' = [0.107, 0.150, -0.129, 0.086] 误差≈0 ✅ B 组 [10.0]：scale = 10/7，q = 7 → W' = 10.0 ✅ 把 outlier 关进它自己那组，不祸害别人 结论：int4 只有 15 个刻度，不用 group-wise 就会被 outlier 一锅端。 这就是「int4 必须 group-wise（group_size=128）」的物理原因。

为什么是 128？存 scale 有开销，太大就亏：

int4 权重：每 128 个 ≈ 128 × 0.5 = 64 字节 每个组存 1 个 scale（fp16）= 2 字节 额外开销 = 2 / 64 = 3.1% ← 几乎可忽略 （若 group_size=32：开销 = 2/16 = 12.5%，太亏） 所以 128 是「精度够用 + 开销小」的工程折中。

讲解3. 板书③：三大方案对比（GPTQ / AWQ / RKNN）

粒度是「怎么切」，方案是「用哪条生产线」。三条线目标不同，别混：

方案类型典型精度要校准集?产物端侧/NPU 适配
GPTQ训练后量化 + 二阶误差补偿int4 / int3是通用权重文件弱（NPU 不直接吃）
AWQ训练后量化，激活感知（保护重要通道）int4是通用权重文件弱（同上）
RKNN瑞芯微官方工具链，per-channel PTQint8 为主是.rknn强（3576 原生）
记住这条分工，面试直接说： GPTQ / AWQ =「通用量化算法」，精度好、压缩狠， 但产物是给 GPU/CPU 框架的，NPU 不直接吃。 RKNN =「平台落地工具」，直接编译成 NPU 能跑的 .rknn， 端侧落地认它。 一句话：算法选 GPTQ/AWQ，落地选 RKNN。 在 RK3576 上，最终一定走 RKNN。

讲解4. 板书④：GGUF 格式（llama.cpp）

GGUF 是 llama.cpp 的模型格式，端侧/CPU 验证最常用。它用块量化（每 32 个一组）实现 group-wise。名字看着乱，看两个就够：

格式位宽/每权重3B 体积特点
Q8_0≈ 8.5 bit≈ 3.2 GB接近原始精度，体积大
Q4_K_M≈ 4.5 bit（混合）≈ 1.9 GB体积/质量最佳，端侧首选
为什么是 8.5 / 4.5 而不是 8 / 4？ 块量化每组要存一个 scale → 有效位宽 = 数据位 + scale 分摊。 Q8_0：8 bit 数据 + 每 32 个 1 个 fp16 scale ≈ +0.5 → 8.5 Q4_K_M：4 bit 为主 + 混合精度 + scale ≈ 4.5 Q4_K_M 是「质量/体积」甜点：比 Q4_0 聪明（重要层用高精度）， 端侧跑 3B 通常就选它做跨平台验证。

讲解5. 板书⑤：选型决策（背下来）

场景 → 方案 RK3576 生产落地 → RKNN int8，per-channel（NPU 原生、最稳） 跨平台 / CPU 验证 → llama.cpp + GGUF Q4_K_M 云侧 / 大模型压榨 → GPTQ / AWQ 被问「RK3576 + 3B 用什么量化」→ 标准答： 「优先 RKNN int8 per-channel，直接吃 NPU；如果要 int4 且想跨平台验证， 用 llama.cpp GGUF Q4_K_M。GPTQ/AWQ 精度好，但 NPU 不直接支持， 不如用 RKNN。」

讲解6. 板书⑥：CV 量化 vs LLM 量化

前面讲的是「通用量化」。但真正的端侧业务里，CV 模型（检测 / 分割）和 LLM 的量化痛点完全不同——一个是坐标回归，一个是词表预测。搞混了就会「LLM 那套调法用在检测上，mAP 掉一半」。

CV 量化 vs LLM 量化：目标不同，敏感点不同 CV 量化（检测/分割） LLM 量化 输入 图像（连续、空间相关） 文本 token（离散） 输出 bbox 坐标 + 掩码/类别 词表概率分布 关键头 回归头（做连续值回归） 最后 logits 层 量化最怕 回归头：连续值，误差直接进坐标 权重/激活里的 outlier 主流评估 mAP（检测）/ mIoU（分割） PPL（困惑度） 对齐手法 回归头/敏感层保高精度 权重分组 + 保护重要通道 一句话：CV 盯"坐标回归准不准"，LLM 盯"权重离群值"。

为什么回归头对量化更敏感、分类头相对鲁棒？用手算把差别算出来：

回归头 vs 分类头：量化噪声谁更能忍？ 设回归头输出归一化 bbox 坐标（0~1），int8 对称量化。 情形 A：动态范围正常，scale = 0.004 单坐标最大误差 = scale/2 = ±0.002 640px 图 → 0.002 × 640 = ±1.3 px → IoU 基本无损 情形 B：范围被别的输入撑大，scale = 0.02 误差 = ±0.01 → 0.01 × 640 = ±6.4 px 20px 的小目标直接偏 1/3 个框 → mAP 掉一大截、小目标漏检 对比分类头：输出是"第几类"，只要 argmax 的最大项没被翻转， 结论就不变——量化噪声被"离散化"吃掉了 → 相对鲁棒。 结论：量化检测/分割模型，重点盯回归头与坐标/掩码精度； 量化 LLM，重点处理权重与激活的离群值。
评估指标别搞混（量化前后跑同一套，看"相对掉点"） CV ：mAP@IoU（检测）、mIoU（分割）——"框得准不准、分得对不对" LLM ：PPL（困惑度）——"预测下一个词有多犹豫"，越大越差 CV 看绝对值（mAP 0.42→0.38 就是掉点），LLM 看 PPL 变化率。

讲解7. 板书⑦：校准集工程要点

PTQ（后面板书⑧）不训练，全靠校准集去"看一眼"每层的真实激活分布。校准集选得好不好，直接决定量化的成败。

校准集（calibration set）是 PTQ 的命门 作用：PTQ 不训练，靠校准集"看一眼"真实激活分布， 据此估出每层激活的 scale / zero_point（量化范围）。 工程要点： 1) 必须覆盖真实输入分布：训练分布 ≠ 线上分布 2) 数量够用即可：常见 100~1000 张/条（RKNN 一般几百张就够） 3) 多样性 > 数量：光照/角度/尺度/类别/难例都要有 4) 别拿"喂熟样本"糊弄：分布偏 → 激活范围估偏 → 白量化
校准集选错的代价（会直接拖垮检测/回归精度） 例 1：校准集全是白天图，线上有夜景 → 激活范围估小 → 夜景激活"溢出"被裁 → 框飞 / 漏检 例 2：校准集漏掉小目标场景 → 回归头动态范围估偏 → 小目标坐标误差被放大 例 3：校准集只覆盖正常对比度，忽略强光/逆光 → 分割边界锯齿、mIoU 掉点 校准不对 = 量化白做。评估掉点，第一件事先怀疑校准集。

讲解8. 板书⑧：PTQ vs QAT 对比

前面三个方案（GPTQ/AWQ/RKNN）本质都是训练后量化。再往上还有一层决策：要不要动训练？这就是 PTQ 与 QAT 的分野。

PTQ（Post-Training Quantization，训练后量化） 做法：模型已训练好，只用校准集估量化参数，不碰训练 优点：快（分钟级）、不需训练流程/算力/标注数据 缺点：精度损失相对大，对 outlier / 敏感层没辙 端侧地位：主力方案（RKNN 的量化就是 PTQ） QAT（Quantization-Aware Training，量化感知训练） 做法：训练时插入"伪量化"节点，让模型在训练中 主动学会适应量化误差 优点：精度更好，可逼近浮点结果 缺点：要完整训练流程 + 算力 + 数据，周期长 端侧地位：精度不达标时的"补救牌" 决策口诀： 端侧落地 → 先 PTQ；PTQ 掉点超预算 → 才上 QAT。 （RKNN 原生支持 PTQ；QAT 需自建训练 pipeline 再导入）

能力标签：能说清「怎么量化、为什么这么量化、在哪落地」——量化选型能力。

RK3576 特别提示

  • 3576 的 NPU 是 int8 定点加速器为主，int4 支持有限且多为 int8 模拟，所以生产上优先 int8 per-channel。
  • RKNN 量化必须给校准集，且要覆盖真实输入分布（后面第 9 章会用真实数据校准）。
  • GPTQ/AWQ 的产物不能直接塞给 NPU，需要转 RKNN——所以端侧落地环节认 RKNN。
  • RKNN 走的就是 PTQ：校准集质量直接决定线上 mAP。做检测/分割时，校准集务必覆盖夜景、小目标、强光/逆光、难例等真实场景，否则激活范围估偏直接拖垮精度。
  • 回归头更敏感：必要时对回归头/敏感层保留更高精度（混合量化），别一刀切 int8。
  • 若 PTQ 掉点超出预算，再考虑 QAT（需自建训练流程）；端侧日常优先 PTQ。
