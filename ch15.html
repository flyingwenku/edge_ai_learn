课堂讲义（板书）

讲解0. 这节课到底学什么

前面各章是「做出来」；这章是「做决策」。端侧系统架构的核心动作就一句话：在成本、功耗、延迟、能力之间做取舍，并说清理由。练法只有一个——拿真实场景反复出方案，直到能条件反射。

讲解1. 板书①：端云协同——什么端侧、什么云端

端侧不是什么都自己干，云端也不是万能。分工原则：高频、低延迟、隐私、离线可用 → 端侧；低频、重算力、要最新知识 → 云端。

端云分工决策表 任务 端侧 云端 ───────────────────────────────────────────── 唤醒词（常驻） ✅ 常驻低功耗 ❌ 语音识别 ASR ✅ 小模型可端侧 ⚠️ 强场景转云 意图识别 ✅ 1.5~3B ❌ 简单多轮对话 ✅ 1.5~3B ❌ 本地知识检索 ✅ RAG ❌ 复杂推理/长文/代码 ❌ 转云 ✅ 大模型 需要最新信息 ❌ → 云 ✅ 隐私敏感数据 ✅ 必须留在端 禁止外发 断网策略：降级到本地 1.5B，只保基础对话 + 本地工具 + RAG。
一句话结论：端云协同的判据是「延迟 / 隐私 / 离线 / 成本」四把尺子——能满足就地端侧，满足不了才上云，且必须设计断网降级路径。

讲解2. 板书②：RK3576 的能力边界（背下来的结论）

做架构要清楚手上的芯片「能吃多大模型」。RK3576 的舒适区很小但很实用。

RK3576 能力边界 舒适区模型规模 ：1.5B ~ 3B int4 / int8 能干的活 ：意图识别、简单多轮对话、RAG 问答、语音唤醒 吃力的活 ：>7B 模型、长上下文(>8K)、复杂数学/代码 真正瓶颈 ：内存带宽（产品 7~11 GB/s，NPU 独占 12~16，峰值 19）—不是 NPU 算力 实测参考 ：3B int4 ≈ 3.5~5.5 tok/s（产品；NPU 独占 6~8，语音交互够用） 结论：3576 = 中端端侧 AI，定位「意图 + 轻对话」，不是「大模型推理机」。 往上要更强：RK3588（带宽更高）；往下要更省：3576 就够。
一句话结论：RK3576 用 1.5B~3B int4 做意图识别和简单对话是甜点；复杂推理走云端，断网降级到本地 1.5B——这条要能脱口而出。

讲解3. 板书③：BOM 成本拆解

方案里必须回答「这台设备物料多少钱」，答不出就是账没算清。BOM 要能拆到主控、内存、存储、传感器、结构。

BOM 拆解模板（示例：本地语音助手） 主控 RK3576 ≈ $12 LPDDR4X 4GB ≈ $6 eMMC 16GB ≈ $3 WiFi/BT 模组 ≈ $3 麦克风阵列(2~4 mic) ≈ $4 扬声器 + Amp ≈ $4 PMIC + 电源 ≈ $2 PCB + 结构 + 组装 ≈ $8 ───────────────────────────── 合计 ≈ $42（留 ~$8 冗余）→ 售价 $49~59 合理 成本敏感点：内存和存储占大头；内存能压到 2~4GB 就别上 8GB。 对照：RK3588 主控更贵（±$10+），BOM 会整体抬高。
一句话结论：BOM 拆解要能报出「主控 / 内存 / 存储 / 外设 / 结构」五块的大致占比，并指出内存与存储是成本杠杆。

讲解4. 板书④：功耗估算与续航

续航不是拍脑袋，是 电池容量 ÷ 平均功耗。平均功耗要从工作剖面推。

功耗估算与续航 待机（仅唤醒词） ≈ 0.3 W 本地 1.5B 语音对话 ≈ 2.5 ~ 3.5 W 峰值（最大推理+喇叭） ≈ 5 W 假设平均 2.5 W，电池 20 Wh（=3.7V × 5400mAh） 续航 = 20 Wh ÷ 2.5 W = 8 h ✅（对齐需求） 要 8h ：电池 ≥ 20 Wh 要 12h：电池 ≥ 30 Wh，或把平均功耗压到 2.0 W 要 4h ：电池 ≥ 10 Wh（可省成本） 常见坑：只按峰值算续航 → 严重高估；要按「带权平均」算。
一句话结论：续航 = 电池容量 ÷ 平均功耗；平均功耗要按工作剖面加权，不能拿峰值或待机糊弄。

讲解5. 板书⑤：一页纸方案模板（本章核心，背下来）

这是本章要你反复练到肌肉记忆的东西。任何端侧 AI 需求，都用这七段回答。

《一页纸架构方案》模板 1. 场景与目标 ：一句话说清「这是什么产品、给谁用」 2. 需求与指标 ：功能清单 + 硬指标（延迟 / 续航 / 成本 / 温度） 3. 端云分工 ：端侧做什么 / 云端做什么 / 断网怎么降级 4. 关键选型 ：SoC / 模型规模 / 量化 / 框架 / 内存预算 5. 成本(BOM) ：主控+内存+存储+外设+结构 ≈ $___ 6. 功耗与续航 ：峰值/平均功耗 → 电池容量 → 续航 7. 风险与取舍 ：最大的 2 个风险 + 应对方案 判据：一页纸、七段齐、每个数字有来源、每个取舍有理由。

拿三个真实场景各走一遍，你会发现「模板不变，数字变」：

场景演练①：本地语音助手 目标：离线可用、隐私、便宜 指标：TTFT<1s, tok/s>4, 续航 8h, BOM $50 端云：端侧全包（唤醒/ASR/意图/对话/RAG），复杂问题转云 选型：RK3576 + 1.5B int4 + RKNN；内存 4GB BOM ：≈ $42 → 售价 $49~59 功耗：平均 2.5W → 20Wh 电池 → 8h 风险：带宽瓶颈 → 靠更狠量化 + 短上下文缓解 场景演练②：车机语音 目标：低延迟、离线安全、车规 指标：TTFT<0.8s, 断网必可用, 宽温 端云：端侧唤醒+意图+短对话；导航/联网内容走云 选型：车规级 SoC 或 RK3576 + 3B int4；内存 8GB BOM ：主控+内存抬高，估算 $___ 功耗：由车电供电，续航不是约束 风险：车规认证 + 热环境 → 降频策略 场景演练③：工业边缘盒子 目标：多路输入、常驻、可靠、可扩展 指标：并发 N 路、7×24 稳定、散热受限 端云：端侧做实时检测/意图；集中管理走云 选型：RK3576 + 1.5B~3B int4；内存 4~8GB BOM ：按路数与接口扩展，估算 $___ 功耗：常驻供电，关注散热与 MTBF 风险：散热→降频；建议无风扇或主动散热
一句话结论：一页纸方案 = 七段模板 × 场景数字；练到「给需求 10 分钟出方案」，就具备了端侧系统架构设计的核心能力。

讲解6. 板书⑥：多模型并发与内存争抢（CV + LLM 同时跑）

真实产品很少「只跑一个 LLM」：摄像头要跑 CV（检测/人脸），耳朵要跑 ASR（唤醒），嘴要跑 LLM 对话——它们共用同一块内存和同一条总线。不做预算就会互相踩脚：轻则掉帧、掉 tok/s，重则 OOM 崩掉。

多模型并发资源预算表（RK3576 / 8GB / 视觉 + 语音助手同时在线） 模块 常驻权重 运行时峰值 带宽需求(NPU 忙) 优先级 ────────────────────────────────────────────────────────────── 系统+驱动+中间件 — 1.00 GB — — 唤醒 + ASR + 声学前端 20 MB 0.10 GB ~1 GB/s 最高 LLM 3B int4 2.00 GB 0.50 GB(KV4K) ~10 GB/s 高 LLM 1.5B int4（降级态） 1.00 GB 0.35 GB(KV4K) ~6 GB/s 高 CV 检测 YOLOv8n int8 4 MB 0.25 GB ~3 GB/s 中（可降帧） CV 分割/pose int8 8 MB 0.20 GB ~2 GB/s 低（可关） 应用 + RAG 索引 — 0.30 GB ~1 GB/s 中 预留（碎片/峰值/OOM 缓冲） — 1.00 GB — — ────────────────────────────────────────────────────────────── 合计(3B + 双 CV) ≈2.03 GB 3.35 GB ≈17 GB/s ⚠ 超总线 合计(1.5B + 单 CV) ≈1.02 GB 3.00 GB ≈11 GB/s ✅ 安全 内存红线：永远留 ≥1GB 预留，见底就主动降级，别等 OOM Killer。 带宽安全线：总线（NPU 独占上沿）≈16 GB/s，留 20% 余量 → 并发安全线 ≈ 12.8 GB/s（产品场景 7~11 更低）。

① 内存怎么分：分三类——常驻权重（开机 mmap，基本不动）、动态运行时（激活 / KV Cache / 工作区，可回收）、预留缓冲（碎片 + 峰值，≥1GB）。给每个模型设内存上限（进程隔离或 cgroup），防止一个模型把另一个挤爆。

② NPU 时间片与优先级：3576 只有一个 NPU（6 TOPS），多模型只能分时复用，且切换只发生在一次推理的边界（不能打断正在算的那一层）。所以给 LLM 的首 token（TTFT）最高优先级、CV 用低优先级 + 降帧；别让长任务霸占 NPU——把大推理拆小、限制单次时长。

③ 带宽争抢：LLM 解码是带宽型（每出一个 token 要把权重搬一遍：3B int4 ≈ 2GB/token），CV 每帧也要搬激活。两者同时跑，总需求叠加 → 谁抢到谁快，另一方 tok/s 或帧率就掉。这正是「CPU 空闲但推理变慢」的原因——瓶颈在带宽，不在算力。

④ OOM 风险与降级顺序：降级要有顺序、有阈值——先牺牲「可重算、体验类」负载，最后才动核心功能；先砍内存大头（KV、模型规模），再砍小头。

降级顺序（从上到下依次触发） ① 可用内存 < 1.5 GB → CV 降帧 30 → 15 fps ② 可用内存 < 1.2 GB → CV 输入 640 → 320，或停「分割/pose」 ③ 可用内存 < 1.0 GB → LLM 上下文 8K → 4K → 2K（缩 KV Cache） ④ 可用内存 < 0.8 GB → LLM 3B → 1.5B（保对话，牺牲理解力） ⑤ 仍不足 → 只保 唤醒 + ASR + 本地工具，聊天转云或排队 原则：先体验后核心；先大对象后小对象；先可降级后不可降级。 红线：宁可主动降级，也不要被动 OOM。
一句话结论：并发预算 = 内存三类分账 + NPU 时间片优先级 + 带宽安全线 + 有序降级；核心动作是「先算账、留缓冲、按阈值降」。

  • 能给「CV + LLM 并发」做内存 / 带宽预算，并说出降级顺序与安全线。

本节要点回顾

要点回顾
  • 端云分工的判据是延迟 / 隐私 / 离线 / 成本四把尺子：高频、低延迟、隐私敏感、要离线可用的放端侧；复杂推理、需要最新知识的放云端，并必须设计断网降级路径。
  • RK3576 能力边界：舒适区 1.5B~3B int4，做意图识别与简单多轮对话；>7B、长上下文、复杂代码吃力；真正瓶颈是内存带宽（峰值 19 / NPU 独占 12~16 / 产品 7~11 GB/s），不是 NPU 算力。
  • BOM 按主控 / 内存 / 存储 / 外设 / 结构五块拆解，内存与存储是成本杠杆；本地语音助手示例合计约 $42，售价 $49~59 合理。
  • 功耗与续航：续航 = 电池容量 ÷ 平均功耗，平均功耗按工作剖面加权；例：平均 2.5 W、20 Wh 电池 → 8 h。
  • 一页纸方案七段模板：场景与目标 / 需求与指标 / 端云分工 / 关键选型 / 成本(BOM) / 功耗与续航 / 风险与取舍——一页纸、七段齐、每个数字有来源。
  • 三个场景（本地语音助手 / 车机语音 / 工业边缘盒子）共用一套模板，变的只是数字与取舍：语音助手看成本续航，车机看可靠性与车规，工业盒子看多路与散热。
  • 多模型并发预算：内存分常驻权重 / 动态运行时 / 预留缓冲三类（预留 ≥1GB）；单核 NPU 只能分时复用，按优先级调度；带宽安全线约 12.8 GB/s（产品更低）。
  • 降级要有顺序、有阈值：先体验后核心、先大对象后小对象、先可降级后不可降级；宁可主动降级，也不要被动 OOM。

RK3576 特别提示

  • 定位要说准：3576 是中端端侧 AI，适合「意图 + 轻对话 + RAG」，不要吹它能跑大模型。
  • 瓶颈是带宽不是算力：方案里写优化方向时，优先「降比特 / 减上下文 / 前缀缓存」，而不是「加算力」。
  • 内存是成本杠杆：4GB 够就跑 4GB，别为了跑更大的模型硬上 8GB，BOM 会顶不住。
  • 升级判断：若要跑 >3B 或长上下文，考虑 RK3588（带宽更高）；中端产品 3576 性价比更优。
