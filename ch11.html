课堂讲义（板书）

讲解0. 这节课到底学什么

语音是端侧交互最自然的入口。它天然分成两段：「先唤醒、再识别」——设备平时只跑一个极小的唤醒词模型（KWS）守着，被唤醒后才启动更大的识别模型（ASR）。这套「阶梯式」设计正是端侧省电省算力的核心思路。

本章的深度定位：你会懂语音处理的物理直觉（为什么要分帧、为什么取对数、为什么用梅尔刻度），会区分流式与整段两种推理，并能用现成模型跑通链路——不需要自己训练声学模型。

讲解1. 板书①：语音三大任务

先分清语音里到底有哪几件事，各自的目标天差地别。

语音三大任务 ① ASR 自动语音识别（Speech → Text） 把一段语音转成文字。输出是整句/整段文本。 关键词：识别率、延迟、流式。 ② KWS 关键词唤醒（Keyword Spotting / Wake Word） 常驻监听，只在听到"你好小X"这类唤醒词时触发。 输出是"命中 / 未命中"（有时带置信度）。 关键词：极低功耗、极低误唤醒、常驻在线。 ③ TTS 语音合成（Text → Speech） 把文字读出来。端侧常用轻量声码器（如 FastSpeech + HiFi-GAN 小型化）。 端侧设计范式：阶梯式（KWS 常驻 → ASR 按需启动 → TTS 回应） 为什么？唤醒词模型只有几百 KB、mW 级功耗，可以一直听； 识别模型大得多，平时不启动，省电省算力。

讲解2. 板书②：代表网络

不用记结构图，记住「名字 + 干什么 + 端侧地位」。

ASR 代表网络 Conformer ：卷积 + 自注意力混合，兼顾局部（语音短时相关） 和全局（长句依赖）。当前主流 ASR 声学模型。 RNN-T ：输入/预测/联合网络三件套，天然支持流式， 边听边出字，实时性好。 Whisper-encoder：Whisper 的编码器部分，特征强、鲁棒， 端侧可取"encoder 走 NPU + 解码另配"的组合。 （Whisper 整体偏大，端侧一般取它的编码器思路） KWS 代表网络（都很小，几百 KB 级） DS-CNN ：深度可分离卷积，MobileNet 思路搬到语音， 参数量极小，端侧最常用。 TC-ResNet ：时间卷积残差网络，几层就够，延迟低。 Keyword-MLP：更极简的 MLP 版本，极致省电，精度略逊。 一句话：ASR 认"说什么"，KWS 认"是不是那句唤醒词"。

讲解3. 板书③：前端处理（MFCC / fbank / STFT）

这一节要懂「是什么、为什么」，不推公式。语音不能直接喂神经网络——要先变成一张「频率随时间变化」的图。

从波形到特征：三步走 原始波形（16kHz，一维）→ ① 分帧 → ② 频域变换 → ③ 取梅尔/取倒谱 ① STFT（短时傅里叶变换）= 分帧 + FFT 为什么分帧？语音短时平稳——几毫秒内可当稳定信号， 太长就不稳了。典型：窗长 25ms、帧移 10ms（有重叠）。 为什么 FFT？人耳关心的是"有哪些频率成分"， 时域波形看不出，转到频域才看得到。 ② fbank（梅尔滤波器组能量） 把 FFT 的线性频率按梅尔刻度压成 40~80 个带。 为什么用梅尔？人耳对低频敏感、高频迟钝， 梅尔刻度就是"人耳感知频率"的近似 → 更贴合听觉。 ③ MFCC（梅尔倒谱系数） 对 fbank 再取 log + DCT（离散余弦变换），压成 13~40 维。 为什么取 log？人耳对响度的感知接近对数。 为什么 DCT？去掉各维之间的相关性，便于建模。 工程取舍： KWS：常用 fbank（40 维），少一步 DCT，算得更省。 ASR：常用 fbank 或 MFCC；现代模型多用 fbank（保留更多信息）。 算术参数： 16kHz，窗长 25ms = 400 采样点；帧移 10ms = 160 采样点 → 每秒 100 帧。1 秒语音 ≈ 100 帧 × 40 维 ≈ 4000 个特征值。

讲解4. 板书④：流式 vs 整段推理

这是语音端侧最关键的取舍——延迟与精度的矛盾。

整段推理（offline / non-streaming） 做法：等一整句说完，再一次性送进模型。 优点：上下文完整，精度通常更好。 缺点：有"说完才出结果"的等待延迟。 适用：录音转写、离线批处理。 流式推理（streaming / online） 做法：音频按小块（chunk）持续喂入，边说边出。 优点：低延迟，交互体验好（字幕跟读）。 缺点：只能看部分上下文，精度略降；实现更复杂 （要维护流式状态 / 缓存）。 适用：实时字幕、语音助手、会议记录。 延迟手算：chunk 越大延迟越高 chunk = 200ms → 话音到结果最少等 ~200ms（还不算模型计算） chunk = 20ms → 延迟低，但每块算一次，调度开销大 工程折中：常见 chunk 20~320ms，按体验目标定。 KWS 天然就是流式的：每 10~30ms 一帧持续判定， 命中即唤醒——它只关心"现在这一小段像不像唤醒词"。

讲解5. 板书⑤：端侧框架选型

KWS：直接上小推理引擎 目标：常驻、省电、mW 级。 选型：RKNN（NPU，片上） 或 TFLite-Micro（MCU，无 OS） 或 CMSIS-NN（Cortex-M）。 特点：模型才几百 KB，直接端到端跑，不需要前后端拆分。 ASR："前端 + 声学模型"组合 典型链路：音频 → 前端特征（MFCC/fbank）→ 声学模型 → 解码 → 文本 端侧做法： · 特征提取（MFCC/fbank）放在 CPU（轻、固定算法） · 声学模型 encoder 走 NPU（这是算力大头） · 解码 / 后处理在 CPU Whisper 类：encoder 走 NPU，解码按平台能力分配。 为什么 KWS 不像 ASR 那样拆前后端？ 因为 KWS 模型本身极小（几百 KB），拆开反而增加开销； 直接"特征 + 网络"一起打包更划算。

讲解6. 板书⑥：评估指标

不同任务看不同指标，别混。手算把它们算出来。

ASR：识别得准不准 WER（词错误率）：按"词"算。WER = (S + D + I) / N S=替换 Substitute，D=删除 Delete，I=插入 Insert，N=参考词数 CER（字错误率）：按"字符"算。中文常用 CER（因为中文分词有歧义）。 CER = (S + D + I) / 字符总数 手算：参考"今天天气怎么样"（6 字），识别"今天天汽怎么样" S=1（气→汽），D=0，I=0 CER = (1 + 0 + 0) / 6 = 16.7% KWS：唤醒得对不对 唤醒率（召回）：真唤醒词被正确触发的比例。低了 → "叫不醒"。 误唤醒率（FAR, false accept rate）：非唤醒词被误触发的比例。 低了才不"乱叫"；常以 次/天 或 次/小时 报。 手算：测试 1000 次真唤醒，命中 970 次 → 唤醒率 = 97% 连续监听 24h，误触发 2 次 → 误唤醒 ≈ 2 次/天 一对矛盾：调低触发阈值 → 唤醒率↑ 但误唤醒也↑； 调高阈值 → 误唤醒↓ 但"叫不醒"。要按产品体验取平衡点。

讲解7. 板书⑦：成熟度——为什么先从 KWS 入手

端侧语音的成熟度阶梯 最成熟 ★★★ KWS / 唤醒词：模型几百 KB、mW 级、可常年在线 较成熟 ★★☆ ASR：模型大些，靠 NPU 能跑，流式在成熟中 成长中 ★☆☆ TTS：端侧轻量声码器可用，音质/自然度仍在提升 为什么唤醒词是"最便宜的语音入口"： ① 模型极小：只有几百 KB（DS-CNN 级），内存/闪存几乎无压力 ② 功耗极低：mW 级常驻，才能"一直听" ③ 任务简单：二分类（像不像唤醒词），不需要语言学建模 ④ 隐私好：不联云、不上传音频，本地判定 工程含义：做端侧语音产品，先用 KWS 把"入口"做稳， 再往上叠加 ASR / TTS——每一级都能独立降级。

讲解8. 板书⑧：量化敏感点

语音链路的量化有两处要小心 ① 前端特征（MFCC / fbank） 特征本身就含对数、动态范围大，量化要留意范围。 通常特征提取在 CPU/定点里完成，量化时保持与训练一致。 ② 声学模型（ASR encoder / KWS 网络） 卷积/注意力层照常量化； 小模型（KWS）对量化更敏感——参数本来就少， 一点误差占比就大 → 掉点明显。 噪声是最隐蔽的敌人 训练集干净、线上有噪声（风噪、回响、多人说话） → 特征分布漂移 → 精度骤降、误唤醒飙升。 对策：训练/校准集里就混入真实噪声（加噪增强）。 小模型掉点明显时的补救： · 校准集覆盖真实噪声场景 · 对前端特征做定点对齐 · 实在不够就上 QAT（量化感知训练）， 让小模型在训练中适应量化误差

讲解10. 板书填空：帧数与特征量手算

16kHz 语音，窗长 25ms、帧移 10ms，自己算，再展开答案。

时长窗长采样点帧移采样点帧数（填）40 维特征量（填）
1 秒400160??
10 秒400160??
点击展开答案（先自己填！）

16kHz 下，窗长 25ms = 16000 × 0.025 = 400 点；帧移 10ms = 16000 × 0.010 = 160 点。
帧率 = 1 / 0.010 = 100 帧/秒。
1 秒 ≈ 100 帧 → 40 维 → 4000 个特征值；10 秒 ≈ 1000 帧 → 40000 个特征值。
要点：帧数决定模型输入长度与计算量；这也是流式推理「按块切分」的物理依据。

检验标准（自测）

  • 能说清 ASR / KWS / TTS 三大任务的目标差异，以及端侧的「阶梯式」设计。
  • 能说出 Conformer / RNN-T / Whisper-encoder 各适合什么，KWS 用 DS-CNN / TC-ResNet 的定位。
  • 能讲清 MFCC / fbank 的每一步「为什么」（分帧、FFT、梅尔刻度、log、DCT）。
  • 能手算帧数：16kHz、25ms 窗、10ms 移 → 100 帧/秒。
  • 能区分流式与整段推理的延迟与精度取舍，并说出 KWS 天然流式的原因。
  • 能说清端侧框架分工：KWS 直接跑小引擎，ASR「前端 + 声学模型、encoder 走 NPU」。
  • 能手算 CER，并解释唤醒率与误唤醒率的矛盾关系。
  • 能说清语音链路的量化敏感点（前端特征 + 声学模型）与噪声对策。

本节要点回顾

  • 端侧语音采用「KWS 常驻 → ASR 按需启动 → TTS 回应」的阶梯式设计，以省电省算力。
  • ASR 主流声学模型是 Conformer / RNN-T / Whisper-encoder；KWS 主流是 DS-CNN / TC-ResNet / Keyword-MLP。
  • 前端特征三步：分帧（25ms/10ms）→ STFT → 梅尔滤波器组；KWS 常用 40 维 fbank，ASR 常用 fbank/MFCC。
  • 16kHz、窗长 25ms、帧移 10ms 对应 100 帧/秒，是延迟与计算量的物理基准。
  • 流式推理低延迟、精度略降；整段推理精度好但有等待延迟；KWS 本身就是流式逐帧判定。
  • 端侧 KWS 直接跑 RKNN / TFLite-Micro；ASR 用「前端 + 声学模型」，encoder 走 NPU。
  • 评估上 ASR 看 WER / CER，KWS 看唤醒率与误唤醒率，两者是一对权衡。
  • 语音量化敏感点在「前端特征」与「声学模型」；小模型（KWS）对量化与噪声都更敏感，必要时用 QAT 与加噪增强。

RK3576 特别提示

  • 3576 的 NPU 适合跑声学模型 encoder（卷积/注意力为主）；前端特征（MFCC/fbank）放 CPU 更快更省整合成本。
  • KWS 模型只有几百 KB，可直接转 int8 .rknn 常驻；若要极致低功耗且上 MCU，则用 TFLite-Micro / CMSIS-NN。
  • 采样率、窗长、帧移、特征维数必须与训练一致；不一致会让精度断崖式下跌，且很难排查。
  • 语音对噪声敏感：校准集与训练集要混入真实风噪、回响、多人说话，否则线上误唤醒飙升。
  • 小模型（KWS）对量化更敏感：int8 PTQ 掉点明显时，优先补校准集特征帧，必要时上 QAT。
  • 流式的 chunk 大小直接决定延迟：按体验目标在 20~320ms 之间折中；KWS 逐帧判定天然低延迟。
